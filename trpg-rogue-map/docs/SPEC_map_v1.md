## `src/mapgen.js`

座標は**区画**単位（D7: 地図は俯瞰）。1区画＝地図の1マス。戦闘の盤面はここでは作らない。

### `makeRng(seed)`

`seed` から決定論的な `() => [0,1)` を返す。同じ seed なら同じ列。

### `linksOf(chapter)`

`scenes[].exits[].to` から**無向**の辺を起こす。

- `to === "ending"` は捨てる
- `a→b` と `b→a` の両方があれば1本にまとめる
- 返り値 `[{ a, b }]`（`a` `b` は `scenes[].id`）

### `depthOf(chapter)`

`scenes[0].id` を起点に、`linksOf` の辺を幅優先でたどった距離。返り値 `{ [id]: 深さ }`。

これがD5の「入口からの遠さの順序」。**生成器が守る唯一の物語上の制約**。

### `generate(chapter, seed, options)`

成功したら地図、失敗したら **`null`**。失敗は異常ではない（V2: 捨てて振り直せばよい）。

```js
{
  rooms:     Map(id → { id, name, x, y, w, h }),   // x,y は左上。区画座標
  corridors: [{ a, b, path: [{x,y}, ...] }],        // 端点の部屋は含まない
  cells:     Map("x,y" → { kind: "room"|"corridor", id? }),
  bounds:    { minX, minY, maxX, maxY }
}
```

`options`（既定値）: `{ roomW: [2,4], roomH: [2,3], gap: [5,8] }`。部屋の幅・高さ・部屋間の距離の範囲。

**手順は2段。閉路があるため、幅優先で置くだけでは足りない。**

1. **全域木を置く。** 未配置の部屋へ繋がる辺を1本ずつ取り、親の部屋から4方向のどれかへ `gap` だけ離して置く。
   `depthOf` が親より大きい部屋は、**入口から遠ざかる向きを優先する**。通路はL字（先に進む向きが選んだ方向）
2. **残りの辺（閉路）を通す。** 両端が既に置かれている辺について、幅優先で経路を探す。
   **他の部屋のマスを通ってはいけない**（既存の通路とは合流してよい）

どちらかで置けなければ `null` を返す。

### 生成器が満たすこと（`test/mapgen.test.mjs` が確かめる）

| # | 条件 | なぜ |
|---|---|---|
| 1 | 全部屋が配置される | — |
| 2 | 部屋どうしが1マス以上離れる | 壁一枚で隣り合うと別々の部屋に見えない |
| 3 | **通路が部屋を貫通しない** | 既知の欠陥の根治。probeで実際に起きた |
| 4 | `linksOf` の全ての辺に対応する通路がある | 閉路を落とさない |
| 5 | 入口から全部屋へ到達できる | — |
| 6 | 同じ seed なら完全に同じ地図 | — |
| 7 | `depthOf` が大きい部屋ほど、入口からの通路の本数が多い（同値は許す） | D5 |

**3が最重要。** これができていないと、部屋と通路の接合部を描けない。

### `generateWithRetry(chapter, seed, maxTries = 200)`

`generate` が `null` を返す間、`seed + 1` で試す。返り値 `{ map, seed }`。
`maxTries` 回とも失敗したら投げる。

実データでの実測は**1発で100%**（2000seed、閉路を含む本当の接続）。再試行は保険。

## `src/expedition.js`

### 移動の単位は「通路1本」

方向を1回選ぶと、**次の部屋まで歩ききる**。1マスずつではない。

- D6が「通路を1本通る＝遭遇の抽選1回」と決めているので、移動の単位と抽選の単位が揃う（3本目でそのまま繋がる）
- スマホ縦持ち（D12）で、長い通路を7回タップさせない

**1マスずつ動く案は採らない。** 上の2つを壊すため。ただし**歩く様子は演出として見せてよい**（灯りが通路を進む）。それは `ui.js` の担当で、状態は行き先に着いた時点で1回だけ変わる。

### `start(map)`

```js
{ at: 入口の部屋id, visited: Set([入口id]), walked: Set(), pos: {x,y} }
```

`walked` は通った通路の集合（`"a-b"` を小さいid順で正規化した文字列）。

### `exitsFrom(state, map)`

いまの部屋から出られる方向。返り値 `[{ dir, to, corridor }]`。
`dir` は `"north" | "east" | "south" | "west"`（**絶対方向。相対方向は使わない — D4**）。

方向は、通路の**最初の1マスがどちらへ出ているか**で決める。

### `move(state, map, dir)`

`exitsFrom` に無い `dir` なら**何もせず `false` を返す**。
あれば `at` を更新し、`visited` と `walked` に足して `true` を返す。

### `lit(state, map)`

見えるマスの集合。**この規則は暫定であり、仕様で確定させない**（→「1本目の主題」）。

初期実装は1つだけ用意する。

- いま居る部屋のマス
- `walked` に入っている通路のマス
- `visited` に入っている部屋のマス
- **いま居る部屋から出ている未踏の通路は、最初の2マスだけ**（そちらに道があることは分かるが、行き先は分からない）

**規則を差し替えられる形にしておく。** 関数1本で完結させ、他から呼ぶのはここだけにする。

# v2 — 歩く（2026-08-14 追加）

v1を実ブラウザで遊んだ作者の指摘による。**v1の仕様を1点撤回する。**

## 撤回: 「移動の単位は通路1本」

v1は「1マスずつ動く案は採らない」と書いた。**理由の1つが誤っていた。**

> D6が「通路を1本通る＝遭遇の抽選1回」と決めているので、移動の単位と抽選の単位が揃う

**移動の粒度と抽選の単位は独立である。** マスごとに歩いても、抽選は「その通路へ初めて入ったとき1回」
で維持できる。3本目の接続は壊れない。

作者の指摘:「通路を一瞬で（それこそローグのように）通り過ぎてしまうので、ゆっくり歩いてほしい。
部屋の中も壁の近くに行ったり、上下左右に動きたい」。

## 変えること

### 1. 移動は1マスずつ

`expedition.js` の `move(state, map, dir)` を **`step(state, map, dir)`** にする。

- 隣のマスが床（部屋または通路）なら、そこへ1マス動いて `true`。壁なら**何もせず `false`**
- `state.pos` が現在地の真値になる。`state.at` は `pos` のあるマスの部屋id（通路上なら `null`）
- `state.visited` / `state.walked` は `pos` の移動にともなって更新する
- **`exitsFrom` は残す。** 3本目（遭遇）が「どの通路へ入ったか」を必要とするため

### 2. 部屋を広げる

いまは `roomW: [2,4]` / `roomH: [2,3]`。**壁際まで歩ける余地が無い。**
`roomW: [4,7]` / `roomH: [3,5]` にする。横縦比の範囲（0.35〜1.0）は変えない。

### 3. 霧を距離で決める

部屋単位ではなくなる。`lit(state, map)` を次に変える。

- **いま見えている範囲**: `state.pos` から一定距離内の床
- **見たことがある範囲**: 一度見えたマスは覚えたまま残す（`state.seen`）。暗く描く
- 部屋に入っただけでその部屋を全部開ける規則は捨てる

**距離の値は決め打ちにしない。** 関数1本にまとめ、差し替えられる形にする（1本目の主題）。

### 4. 画面は現在地に追従する

`viewBox` を地図全体ではなく、**現在地を中心にした固定の大きさ**にする。

- 大きさは画面の縦横比から決める。マス数で持つ（例: 幅18マス）
- **ドラッグで視点をずらせる。指を離してもずらしたまま。**
  現在地へ帰るのは `戻す` を押したときだけ。
  （当初『指を離すと復帰する』と書いたが誤り。それでは見回せず、`戻す` の意味も無くなる）
- **地図のタップでは移動しない。** ドラッグ＝視点、ボタン＝移動。1つの面に2つの機能を置かない

### 5. 灯りに揺らぎ

CSSアニメーションだけで作る。部品を増やさない。

- 明るさと大きさをわずかに揺らす。**周期を一定にしない**（一定だと機械に見える）
- `@media (prefers-reduced-motion: reduce)` で止める
- **文字と地図の可読性を落とさない。** 揺れて読めなくなるなら弱める

### 6. 長押しで歩き続ける

方向ボタンを押している間、一定間隔で `step` を繰り返す。速さは「ゆっくり歩く」が読み取れる程度。
**値は決め打ちにせず、1か所の定数にする。**

## 検査

`test/mapgen.test.mjs` に足す。

- `step` が壁の方向で `false` を返し、`state` を変えないこと
- 部屋の中で上下左右に動けること（幅4以上の部屋で、横に2マス以上動ける）
- 通路を端から端まで `step` で通り抜けられること

`test/screen.test.mjs` に足す。

- 移動しても**移動ボタンが画面内にあること**（既存の6画面で）
- ドラッグで視点が動き、`戻す`で現在地へ帰ること
- **`prefers-reduced-motion: reduce` で揺らぎが止まること**

## v2でもやらないこと

v1の「やらないこと」はすべて有効。加えて:

- 地図のタップによる移動
- 経路の自動探索（目的地を押すと歩いていく）

## 3. 通路と部屋の接触を出入口だけにする（不具合）

**実測（2026-08-14）:**

- 繋いでいない部屋に接している通路: **200seed中18/67 で発生**
- 遊んでいる seed 1 では、6本すべての通路が自分の部屋に **2〜6マス**接している（出入口は1マスであるべき）
- **この制約を満たす地図は 991件中0件。振り直しでは直らない。置き方を変える必要がある**

### 満たすべき条件

```
通路の各マスについて:
  - 繋いでいない部屋のマスと、上下左右で隣接してはいけない
  - 端点の部屋との隣接は、各端で【ちょうど1マス】（＝出入口）
```

### 原因（読んで確認済み）

`treeCandidate` が部屋の縁から出た直後に曲がれるため、通路が壁沿いを走って融合する。
`routeBetween`（閉路用）の幅優先も、部屋の**マス**しか避けておらず、**隣接**を見ていない。

### 直し方（案。これに縛らない）

- 部屋から出たら、**曲がる前に垂直へ2マス以上進む**
- `routeBetween` の通行可能判定を「部屋のマスでない」から「**部屋のマスに隣接しない**」へ変える
  （ただし出入口の前後は例外）

**方法は問わない。上の条件を満たせばよい。** 満たせない場合は `generate` が `null` を返し、
`generateWithRetry` が次のseedを引く。ただし成功率が実用的（数十seed以内で当たる）であること。

### 検査（必須）

`test/mapgen.test.mjs` に足す。**この検査が効くことを、条件を外して赤くなることで確認する。**

- 100seedすべてで、上の2条件を満たすこと
- 生成成功率を出力すること（何seedに1回当たるか分かるように）

## 経緯（同じ失敗を繰り返さないために）

- v2で1マスずつの移動を入れた → 作者の要望「通路をゆっくり歩きたい」に対応
- v3で「最初に戻してほしい」を受けて**1マスずつを外した**
- **その副作用（通路の途中という位置が消え、通路中の戦闘が成立しなくなる）を伝えなかった**
- 作者の指摘:「この挙動だと通路移動中の戦闘が発生しない。2回目？」

**移動の粒度と遭遇の単位は独立ではない。** 通路の中で戦うには、通路の中に位置が要る。

| | 通路1本ずつ | 1マスずつ |
|---|---|---|
| 遭遇の抽選 | できる | できる |
| **通路の途中という位置** | **無い** | ある |
| 戦闘から数マス下がる | できない | できる |

## 戻すもの（v2の形）

- `step(state, map, dir)` による**1マスずつ**の移動。壁なら `false`
- 方向ボタンの**長押しで歩き続ける**
- **現在地への追従**（`viewWidth` はマス数）
- **ドラッグで視点をずらす。指を離してもずらしたまま。`戻す` で現在地へ復帰**
- 灯りの揺らぎ（`prefers-reduced-motion` で停止）
- 部屋の名前

## 変えるもの（ここが本題）

### 1. 床は1つの面。均一な色

**マスごとに図形を置かない。マスごとに明るさを変えない。**
作者の指摘:「グラデでマスを色分けしたいとは一言も言っていません」。

`src/draw.js` を使う（作成済み・作者が見た目を確認済み）。

```
部屋   roomShapes()      角丸の矩形1つ
通路   corridorShapes()  太い折れ線1本
色     全部同じ。1つの塗り
輪郭   roughFilter()     feTurbulence + feDisplacementMap
```

### 2. 壁は、その面の輪郭

床の図形に `stroke` を掛けるだけ。**別に線を引かない**（v3の直前に入れたマス単位の壁は使わない）。
部屋は囲まれ、通路は2本の線に見える。出入口は通路と部屋が繋がっているので自然に空く。

### 3. 光は連続したマスク

放射グラデーションの**マスク1枚**で、灯りからの距離を表す。
**マス単位の `fill-opacity` を使わない**（これがマス目の正体だった）。

```
覚えている範囲   薄い一律の明るさで描く
いま見えている   同じ図形を、灯りのマスクを掛けて重ねる
```

### 4. 通路は歩いた範囲だけ描く

`corridor.path` のうち `state.seen` にあるマスだけで折れ線を作る。
未踏の通路は入口の2マスだけ（v2の規則を維持）。

## 抜けないこと（不具合の再発防止）

v3で直した「通路と部屋の接触は出入口の1マスだけ」を**維持する**。
`mapgen.js` の該当部分と検査を消さない。

実測（v3で確認済み）: 生成成功257件すべてが条件を満たす（修正前は991件中0件）。
