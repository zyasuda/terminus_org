## これは何か

『廃坑の灯』B1の**遠征モジュール**の試作。村→迷宮→探索→物語→帰還のループを、独立した場所で試す。

構想の正本は BORG の `Inbox/ゲームブック_ローグ_ウィザードリィ融合構想_2026-08-14.md`。
このセッションでの決定と経緯は `docs/HANDOFF_2026-08-14.md`。

```
作者      作品としての判断・実プレイ
Claude    設計・仕様書・検証（実ブラウザ）・修正の妥当性判断
```

**実装はCodexへ非同期で委譲する。** 委譲時のモデルと推論レベルは固定。

```

```

欠陥があれば自分で直す（往復を増やさない）。同じファイルをClaudeとCodexが並行して触らない。

## 足回り

依存パッケージ0件・ビルド無しの素のESM。`fetch` でJSONを読むので `file://` では動かない。

```
npm run serve     # → http://localhost:8123/（キャッシュ無効）
npm test
```

**`python3 -m http.server` を使わない。** `Last-Modified` を返すため、編集した分が届かないまま
検証が空振りする。gamebookで4周のうち3周を無駄にした。`serve.py` は毎回 `no-store` を返す。

## 検証

### `npm test` が緑でも、動く保証にはならない

UIを変えたら必ず実ブラウザで操作し、スクリーンショットを見る。
Playwrightはグローバルに入っている（`/Users/yasuda_k/.nvm/versions/node/v20.14.0/lib/node_modules/playwright`）。

```js
import { chromium } from "/Users/yasuda_k/.nvm/versions/node/v20.14.0/lib/node_modules/playwright/index.mjs";
```

`button[data-x='y']` のようなセレクタで直接叩くのは、内部を知っている者の経路であって検証ではない。
**作者と同じ画面・同じ順で、1つの作業を最後まで通す。**

### 遠征モジュール固有の受入条件

1. 100個のseedすべてで、入口から物語部屋と階段候補へ到達できる
2. 物語部屋の達成前に下り階段を使えない／達成後に使える
3. 帰還後に再開しても、地図・探索済み・撃破済みが一致する
4. 未踏通路の通常遭遇は一回だけ起きる
5. **初見の作者が、地図を見て現在地・戻り道・新しい階段を判断できる**

5だけはコードでは測れない。作者に短く遊んでもらう。

## 書き方

- 判定ロジックは1か所に集める。描画は描画だけ、判定は判定だけ
- `Math.random` を判定側で直接呼ばない。必ず `rng` を渡す（seed再現のため）
- コメントは**なぜそうしたか**を書く。何をしているかはコードが言う

## 進め方の掟（gamebookで払った授業料）

### 測るまで断定しない

「たぶん壊れている」と「2000回中1153回で壊れた」では、判断材料としての価値が違う。
**検索が空振りしたことを「無い」と読まない。** 複数行にまたがるCSSを1行で検索して
「CSSが1つも無い」と報告し、実際にはあった。実物を開いて確かめる。

### UIを足す前に3つ

1. **作者が押す順番を手数まで書き出す。3手を超えるなら設計をやり直す**
2. その手順を、内部を知らない状態で1回通す
3. 触る場所が増えるなら作らない。既にある場所に入るかを先に問う

gamebookで同じ失敗を2回した。どちらも**エンジンのデータの形をそのまま作者に見せた**。
どちらも「表示されること」を確かめ、「使えること」を確かめなかった。

### 最初の一口を小さく保つ

縦切りは1本ずつ。「生成器＋到達可能性検査＋2D表示」で1本、物語・戦闘・帰還の接続は別。
1本目が通らなければ、2本目を作る意味がない。
