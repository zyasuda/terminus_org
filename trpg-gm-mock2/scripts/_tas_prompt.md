mock2側の `npm run check:assets` および実プレイで、TASが出力したキャンペーンデータに関する不具合と、認識のズレが見つかりました。特に「0.」は`parallax`という仕組みそのものの説明なので、まずここを読んでください。

## 0. 前提知識: `parallax`とは何か

### 目的
シーンの背景に奥行きと「静止画だが生きている感じ」を出すための演出です。具体的には、**遠景(空)がゆっくり無限に横スクロールし続け、手前の地形・構造物(前景)は動かず固定**という2層構成にすることで、視差(パララックス)効果を出します。単層の1枚絵では出せない演出です。

### データ構造
章JSONの各シーンに、以下の形で任意設定します。
```json
"parallax": {
  "sky": "xxxx.jpg",   // 遠景・空レイヤー
  "fg": "xxxx.png"     // 前景レイヤー(透過PNG)
}
```

### `img`との関係(ここが今回の混乱の核心)
- `img`は**`parallax`が無いシーン専用の、単層フォールバック**です。
- そのシーンに`parallax`が設定されている場合、mock2は`img`を使わず**`parallax.sky`+`parallax.fg`の2層合成だけを実際に画面へ表示**します。`img`はその場合いっさい参照されません。
- つまり「`parallax`があるシーンの見た目を変えたい」ときに`img`だけ更新しても、画面には何も反映されません(今回発生した不具合はこれです)。

### 適用範囲(重要な誤解ポイント)
`parallax`は特定のシーン専用の特殊仕様ではなく、**どのシーンにも設定できる標準機能**です。とくに屋外シーンでは基本的に使う想定です(今回たまたま屋内シーンが多く、`parallax`未設定のシーンが目立っていただけで、「屋内だから`parallax`を使わない」という設計ではありません)。

### あるシーンで`parallax`を「使わない」にしたい場合
`parallax`キーそのものを**省略**してください。`useParallax: false`のような専用の無効化フラグはmock2のスキーマに存在せず、コードのどこからも読まれません(今回、実際にこのフィールドが追加されていましたが、静かに無視されるだけで何の効果もありませんでした)。

### 各レイヤーの技術仕様
- **`parallax.sky`(空レイヤー)**
  - 想定サイズ: 2400×1080
  - `background-repeat: repeat-x`で**横方向に無限リピート**され、`background-position-x`を0→-2400pxへ720秒かけて動かし続け、1周後は0に戻ってループします。
  - そのため**画像の左端と右端が、横に並べて繋げたときに違和感なく繋がるデザイン(シームレスタイル)である必要**があります。継ぎ目が見えると、ループのたびに画面上で目立つ縦線・ずれが出ます。
  - 横幅が2400pxからずれると、ループ地点でずれ・二重表示が発生します。
- **`parallax.fg`(前景レイヤー)**
  - 想定サイズ: 1920×1080、アルファチャンネル付きの透過PNG
  - `background-size: cover` / `background-position: center` / リピートなしで1回だけ表示されます。
  - シーンの地面・構造物・小物など「動かない手前の要素」を描き、**空が見える部分だけ透明にしてください**(透明部分から`parallax.sky`が透けて見えます)。
  - 単層版(`img`)も別途作る場合は、この前景レイヤーと同じ意匠・構図にしてください。

### 運用ルール(今後お願いしたいこと)
- シーンの絵を新規生成・更新する際は、まず該当シーンに`parallax`が設定されているか確認してください。設定されている場合、`img`ではなく**`parallax.sky`と`parallax.fg`の両方を、新しい絵作りに合わせて一緒に再生成・更新**してください。
- あるシーンに新しく`parallax`演出を追加したい場合も、`img`一枚だけでなく`parallax.sky`/`parallax.fg`の2枚を用意してください。
- `parallax`を使わせたくない場合は、キー自体を省略する(専用フラグを追加しない)。

以下、今回見つかった個別の不具合・要望です。

## 1. 修正済み(報告のみ): chapter_01.jsonの画像パス形式の不統一

`chapter_01.json` の `scenes[1].enemy.sprite`(錆喰い)だけが `"/images/s2_rust_eater.png"` という、先頭に `/images/` が付いた値になっていました。他の画像参照フィールド(`img`・`bg`・`sprite`等)はすべてプレフィックスなしのファイル名(例: `"s3_guardian.png"`)なので、この1件だけ形式が違います。

mock2側の表示コードは `sprite` の値に対して常に `/images/` を前置してURLを組み立てるため、プレフィックス込みの値を渡すと `/images//images/s2_rust_eater.png` のような二重パスになり、画像が読み込めなくなっていました(mock2側で `s2_rust_eater.png` に修正して解決済みです)。

**お願い**: 今後の出力でも、画像参照フィールドは常にファイル名のみ(`/images/`等のプレフィックスなし)で統一してください。

## 2. 対応要望: assets.jsonに同一ファイルの重複登録が発生している

今回の更新で、`assets.json` に「手入力で管理されている既存エントリ」と「TASが新規に追加した `-jpg`/`-png` サフィックス付きの `candidate` エントリ」が、同じ物理ファイルに対して二重に存在する状態になっています。

例:
- `mine_entrance`(status: approved, file: mine_entrance.png)と `mine_entrance-jpg`(status: candidate, file: mine_entrance.jpg)
- `s2_rust_eater` と `s2_rust_eater-png`
- `s3_guardian` と `s3_guardian-png`
- `s4_myra_room` と `s4_myra_room-jpg`
- `s4_myra` と `s4_myra-png`
- `portrait_gareth_alt` と `portrait_gareth_alt-png`
- `portrait_lydia_alt` と `portrait_lydia_alt-png`

このうち `mine_entrance-jpg` は、参照先の `mine_entrance.jpg` が既に削除されて `mine_entrance.png` に差し替わっていたため、存在しないファイルを指す孤立エントリになっていました(mock2側でこのエントリを削除して解決済みです)。

**お願い**:
- 既存のファイルに対して新しく `candidate` エントリを追加する代わりに、既存の承認済みエントリ(`status: approved`)を更新する形にしてほしい(同じファイルに2つのIDが振られると、どちらが正なのか・usedByをどちらに書くべきかが曖昧になります)。
- ファイルの拡張子や名前が変わって古いファイルを削除する場合は、対応する古いassets.jsonエントリも同時に削除・更新してほしい(参照先が存在しないエントリが残ると、mock2側のアセットチェックが誤検知を出し続けます)。

## 3. 参考: usedByの過不足(低優先度)

`s3_guardian` / `s3_guardian-png` の `usedBy` は `chapter_01.scenes.3.enemy.sprite` のみですが、実際のコードでは同じ画像がNPC表示(`npcSprite`)としても使われる場合があります。実害はありませんが、余裕があれば `usedBy` に `chapter_01.scenes.3.npcSprite` も追加してもらえると、mock2側のアセットチェックの警告が減ります。

## 4. 経緯報告: シーン1(坑道の入り口)で実際に起きたこと

1. シーン1の絵を新しくしてもらった際、`img: "mine_entrance.png"`だけが新しくなり、既存の`parallax: {sky: "s1_sky.jpg", fg: "s1_foreground.png"}`は旧デザインのままでした。「0.」の通り`parallax`があるシーンでは`img`は使われないため、更新が画面に反映されませんでした。
2. その後の更新で、`parallax`キーごと削除し、代わりに`useParallax: false`を追加する対応がされていました。これは「0.」で説明した通りmock2のスキーマに存在しない無効なフィールドで、静かに無視されるだけでした。`parallax`を消したことで2層合成自体が無くなり、`img`(`mine_entrance.png`)が単層でそのまま表示される状態になりました。
3. さらに`mine_entrance.png`自体を確認したところ、左上に山の稜線の形をした透過(アルファ0)領域があり、**単層の完成画ではなく、そもそもパララックス前景(fg)用に作られた画像**でした。そのため単層`img`として使うと、透過部分から下地の暗いグラデーション(フォールバック用)が透けて見え、「空だけ反映されていない」という見た目になっていました。

**mock2側で以下の対応をしました**(これ以上そちらで対応不要です):
- `chapter_01.json`のシーン1に`parallax`を復活させ、`fg: "mine_entrance.png"`として正しく前景レイヤーに割り当てました(この画像はfg用の透過デザインのまま、これでそのまま使えます)。
- 無効な`useParallax`フィールドは削除しました。

**そちらに新しくお願いしたいのは1点だけ**です。
- 現在`parallax.sky`は暫定的に旧デザインの`s1_sky.jpg`のままです。`mine_entrance.png`(新しい絵作り: トロッコ・タグ付きの看板・照明の雰囲気等)に合う新しい空レイヤーを、「0.」の技術仕様(2400×1080、左右の端が繋がるシームレスタイル)で再生成してください。ファイル名は`s1_sky.jpg`のまま上書きしてもらって構いません。

## 5. 修正済み(報告のみ): シーン3の`direction`に自己矛盾した指示が混在していた

シーン3(灯りの部屋)の`direction`フィールドに、以下の2つの指示が同居していました。

1. 「番人に敵意がないことを、**正体を明かさずに佇まいと所作で示唆せよ**...脅威ではなく孤独と献身を感じさせる存在として描け」(=喋らせず、非言語の演出だけで伝える指示)
2. 「【TAS発話ルール】「胸の光るもの」の開示後に**NPCが**「胸の周りに付着している青い欠片を手に取った。」**と伝える**（一度だけ）」(=NPCに明示的に発話させる指示)

`direction`はmock2のGMプロンプトにそのまま埋め込まれるため、LLMは指示2に従って番人に一言喋らせてしまい、指示1(黙って佇まいだけで示す)と矛盾する結果になっていました。

**お願い**: `direction`のような「LLMへの演出指示」フィールドに複数の指示を書く際は、同じ対象(この場合は番人というキャラクター)についての発話方針(喋らせる/喋らせない)を1つのフィールド内で矛盾させないよう、追記前に既存の指示と読み合わせてください。今回は「喋らせない」の方針を採用し、mock2側で発話ルールの一文を削除して解決しました。今後、同様の「◯◯ルール」を追記する形で情報を積み増す運用をする場合は、既存の`direction`本文と矛盾しないか確認する工程を入れることをお願いします。
