# 戦闘グリッド 実装ステータス

設計の正本は `docs/BATTLE_GRID_DESIGN.md`。このファイルは「今どこまで終わったか」を追うための作業用メモで、フェーズが進むたびに更新する。

最終更新: 2026-07-27

## 進め方の合意(2026-07-27)

- 現行のCombat v1は**リセットして作り直す**。戦闘は独立したシステム・独立した画面とし、mock2本体とは**戦闘前後の状態を受け渡すデータだけ**で接続する
- フェーズごとにブランチを切り、そのフェーズが終わったら`main`へマージして次のブランチを切る(ブランチを長生きさせない)
- 実装言語はまずJS + Three.js。必要になった部分だけ後からRustへ切り出す

### GMと発話の扱い(決定)

現行の「システムが確定 → GMが語る」という大原則をグリッド戦闘でもそのまま引き継ぐ。

| 要素 | 扱い |
|---|---|
| 移動可否・命中・ダメージ・包囲倍率 | **システムが確定**(`src/battle/core.js`)。LLMは介入しない |
| ダメージ・状態変化の説明 | **GMが語る**。ログに残る形で表示する(現行の左パネル「GMの語り」相当) |
| 同行者・敵の発言 | **吹き出し**で表示する(現行の`companionBubbles`と同じ扱い) |

したがって`core.js`は文言を一切持たず、「何が起きたか」を構造化して返すだけにする。語りと描画はその結果を表現するだけで、結果を変えない。

## 動かし方

```bash
npm run dev          # https://localhost:5173/battle を開く
npm run test:battle  # 盤面ロジックの自己チェック(ブラウザ不要)
npm run smoke:battle # ブラウザで描画・操作・交戦まで通るか確認(要 npm run dev)
```

URLパラメータ:

- `?fixture=melee` … 敵と隣接した状態から始まる(交戦中の挙動を毎回同じ手順で確認するため)
- `?seed=42` … 障害物の配置を固定する。無指定なら起動のたびに変わる

### フェーズ1でやったこと

- `src/battle/core.js`: 盤面の事実だけを確定する純粋関数群。Three.js・React・LLMに非依存
  - グリッド生成(ASCIIマップ、`#`=壁。行長が不揃いでも可変形状として扱う)
  - 8方向の隣接判定(近接攻撃の射程)
  - 移動力(基本3 + agility補正+1〜+3)と、BFSによる到達範囲の列挙
  - 包囲ボーナス(倍率 = 1 + (隣接人数−1)/3)
  - 行動順(agility降順、戦闘不能は除外)
  - 近接攻撃の解決(d20は外から注入。命中・クリティカル・ファンブル・包囲倍率・ダメージを確定)
- `src/battle/core.test.mjs`: node標準の`assert`だけの自己チェック。`npm run test:battle`で実行
- `src/battle/core.js`に仮置きの敵AI(`chooseEnemyAction`)を追加。最も近い相手へ寄り、隣接していれば殴るだけ
- `src/battle/view3d.js`: Three.jsの描画。ルールは持たず、確定した盤面を見せるだけ
  - 正射影カメラ、Y軸90度刻みの4方向固定(切り替えはなめらかに補間する)
  - 床タイル(厚み0.25)・壁・ユニットをすべて色付きの箱で表示。キャラのアセットはまだ使わない
  - クリックでマス/ユニットを拾う(ユニットを床より優先。敵の足元を押しても攻撃対象になる)
- `src/battle/BattleView.jsx`: 手番の流れ・入力・HUD・ログ。`/battle`で開く別画面
- `src/battle/smoke.mjs`: ブラウザでの確認。`npm run smoke:battle`

### Phase 1で実際に動かして分かったこと(と、その調整)

- 盤面・移動・隣接・包囲・命中・敵の接近と攻撃まで、一通り動作することをブラウザで確認した
- **攻撃できる相手が分からない問題**があったため、対象の足元のマスを塗るのをやめ、相手自身を光らせるように直した(マスを塗っても本体の箱に隠れて見えなかった)
- **移動力が広すぎた**: agility7のガレスは移動力6で、8x8の盤面だとほぼ全域が移動先になり、位置取りの意味が薄れていた
  - → 一度は盤面を12x10へ広げたが、**8x8を基本として作り込む**方針に決まったため8x8へ戻し、移動力の側をさらに半分へ落とした。現在は基本1 + agility補正(+1〜+2)で**合計2〜3**。一手で盤面の1/4ほどしか動けないので、どこへ寄るかの判断が効く
- **包囲ボーナスが通常攻撃では効かなかった**: 「2人で囲んでいる(×1.33)」と表示されつつダメージは1のまま(1×1.33の四捨五入で1)。倍率が効くのはクリティカル時だけだった
  - → 基礎ダメージを1固定から**ユニットの`atk`(既定3)**に変えた。倍率に意味のある解像度が生まれ、atk3なら1人3 / 2人4 / 3人5 / 4人6と一段ずつ増える
  - HPも合わせて調整(ガレス16 / リディア14 / 錆喰い10)。片方が一瞬で溶けない程度の長さにした

### 盤面と見た目(2026-07-27)

- **盤面は8x8を基本**とする。素の盤面は全面が床で、遮蔽は起動のたびにランダムに散らす(左右対称だと展開が読めてしまうため)
  - 高さ1.0 = 柱。進入できない
  - 高さ0.25 / 0.5 / 0.75 = 瓦礫。乗り越えられるので進入でき、視線も遮らない。Phase 2で飛び道具の通過率(1−高さ)に効く
  - 配置は決定論PRNG(mulberry32)なので`?seed=`で再現できる。開始位置には置かず、両陣営が行き来できなくなる柱は取り消すため、通り抜け不能な盤面にはならない
- **ユニットの形**: 味方は円錐の胴体+頂点に頭の球、敵は三角柱。ボードゲームの駒のような見た目で、輪郭だけで陣営が分かる
  - これはPhase 3(ビルボード vs 3Dモデル)の判断が済むまでの仮の形

### ヒット演出(2026-07-27追加)

すべて見た目だけの一時的な表示で、`core.js`が確定した結果は変えない。

- 命中位置に広がって消える衝撃の輪(クリティカルは金色で大きめ)
- damage値が浮き上がりながら消える(canvasテクスチャのスプライト)
- 被弾したユニットが一瞬光る
- 画面の揺れ(クリティカルは強め)。基本カメラの上に一時的に重ねるだけで、カメラの目標位置は動かさない
- 空振りは薄いグレーの輪だけ

## 仮置きの値・後で調整する判断

実装は入れたが、手触りを見て変える前提のもの。

- **包囲ボーナスの倍率**: 設計書どおり1 + (人数−1)/3。基礎ダメージを`atk`にしたことで一段ずつ増えるようになったが、数値そのものは仮置き
- **ダメージとHPの数値**: atk(ガレス3 / リディア2 / 錆喰い2)、HP(16 / 14 / 10)、`defenseDc` 12(d20で45%命中)。1体を倒すのに4回前後の命中が要る想定
- **斜め移動のコスト**: 1マス1コスト(チェビシェフ距離)。近接射程が8方向隣接なので移動も8方向で揃えた。斜めを1.5にしたい場合は`reachableCells`だけ直せばよい
- **他ユニットのマス**: 通過も着地も不可。味方のすり抜けを許すなら`reachableCells`の`blocked`の作り方を変える
- **移動力**: 基本1 + agility補正(7以上=+2 / それ未満=+1)。8x8に対して合計2〜3。盤面が広がったら段を増やす
- **障害物の数**: 柱5・瓦礫6(8x8=64マスに対して約17%)
