# 戦闘グリッドシステム設計(2026-07-25 ブレスト)

現行の物語シーン(背景画像+スプライト)とは完全に別画面として、アイソメトリックのグリッド戦闘を新設する構想。データ層は共有ストア経由で受け渡し、描画は完全分離する。実装言語(Rust/WASM or JS+Three.js)は未確定だが、mock段階ではJS/Three.jsで手触りを検証し、必要になった部分だけRustへ切り出す方針。

## グリッド仕様

- ベースはマインクラフト風の正方形グリッド。データ構造は素直な2次元配列とし、「通行可能かどうか」をセルごとのフラグで持つ(壁=進入不可セル)。これにより長方形以外の形状(通路、部屋、行き止まりなど)も配列自体を可変形状にせず表現できる
- 高さは0.25刻み(1キューブ=4層)。地形高さは見た目・足場としての演出用であり、射線判定には影響させない(高い場所に立っても障害物越しには見えない、という単純な二値ルールを採用)
- 生成方針: 敵/シーンごとに大まかな「型」(通路型・小部屋型・広間型など)を選び、その型の中で高さや障害物の配置をランダム生成する2段構成。完全ランダム生成は採用しない

## 障害物・射線

障害物は地形高さとは別レイヤー(柱・瓦礫・木箱など、そのマスの上に乗るオブジェクト)として持つ。

- **視認/ターゲット可否**: 高さ1.0(フル)の障害物は視認・ターゲットを完全に遮断する単純な二値ルール。攻撃者側の高低差(高い場所にいるかどうか)は考慮しない
- **飛び道具・リーチ攻撃の通過判定**: 高さ1.0未満の障害物(0.25/0.5/0.75)は視認自体は遮らないが、攻撃が物理的に通過できるかを別途判定する。通過率 = 1 − 障害物の高さ(0.25→75%、0.5→50%、0.75→25%、1.0→0%)
  - 経路上に複数の障害物がある場合、**最大高さの障害物1つだけ**で判定する(掛け算で複合させない)
  - 判定は既存のd20命中判定とは独立した通過チェックとして先に行う。通過に失敗したら攻撃は障害物に当たって不成立、成功すれば通常の命中判定に進む
- **近接攻撃(8方向隣接のみ、リーチ武器は保留)は障害物の影響を受けない**。隣接=間にセルが存在しないため、障害物が「隣接する2マスの間」に挟まる状況はそもそも定義上起こり得ない。将来リーチ武器を追加する際は、上記の通過率判定をそのまま流用できる

## 移動

- 基本は1マスずつのグリッド移動
- 俊敏性(agility)パラメータにより移動力ボーナス(+1〜+3)を付与
- 移動力を使い切って隣接すれば同ターン内で攻撃可能。移動力を残したまま攻撃してターン終了、という選択も可

## 近接攻撃

- 射程は8方向隣接のみ(リーチ武器の射程は保留、後日検討)
- 背面攻撃はマス位置による自動判定ではなく、キャラクター固有スキル扱いとする

## 包囲ボーナス(ZOC的)

敵に隣接している味方の人数に応じてダメージ倍率が段階的に上昇する(8方向を全部埋める必要はなく、人数に応じた比例ボーナス)。

- 倍率 = 1 + (隣接人数 − 1) × (1/3)
- 1人: ×1.00 / 2人: ×1.33 / 3人: ×1.67 / 4人(フル4人パーティ): ×2.00
- 上記の数値は仮置き。実プレイでの手触りを見て後日調整する

## マップの見た目(プレーンマップ例: 8x8)

- 床タイル(厚さ0.25)を敷き詰める
- 外壁は固定向きの平面(`PlaneGeometry`。カメラに追従する`Sprite`/ビルボードではない)を四隅にピッチリ正確に配置。紙工作・ジオラマ的な「書き割り」の位置づけで、グリッド外の背景装飾であり、上記の高さ・障害物・射線ルールには一切関与しない
- カメラは基本4方向固定(Y軸90度刻み)+演出時のみ自由アングルカメラを使う可能性あり

## キャラクター/モンスターの表現(未決定)

- 環境(壁・床)は紙工作風のフラットな表現、キャラクター/モンスターは「彩色されたフィギュア」のような立体感のある表現にしたい、という方向性
- **ビルボード(平面スプライト) vs 実3Dモデルは未決定**。ゲーム性・商品性に直結する肝の判断のため、コンセプトデザインを見てから決定する予定
  - 判断材料: 演出カメラが完全自由(上下含め回り込み可能)だと平面ビルボードは斜め下から見た時に「紙のように薄い」ことが露呈するリスクがある。カメラの見下ろし角度が固定(水平回転のみ)であれば、垂直軸のみ追従する円柱ビルボードで違和感なく成立する
- Zソート(奥行きの重なり順)はThree.jsの透過オブジェクト自動ソートを利用する想定。アルファテスト(二値透過、輪郭がにじまない)を使うと描画順の破綻を避けやすく、紙工作の切り抜き感にも合う
- 人型キャラの標準身長は2〜2.5ブロック程度(マイクラキャラ相当)。高身長の敵は許容する
- 大型モンスター(例: ドラゴンは4x4x4)は複数マスにまたがる「マルチセル占有」になる。これに伴う移動・隣接判定・包囲ボーナスの扱いは別途検討が必要(未着手)

## Combat v1(現行)との関係

このグリッド戦闘が稼働した時点で、現行の`COMBAT_SPEC.md` v1(決定論ターン制ロジック)は**100%置き換え**予定。以下は新システム向けに再設計が必要:

- 同行者の戦闘中自動行動(攻撃60%/防御20%/一言20%のランダム抽選) → マス目上の移動・位置取りを考慮したAIへの再設計が必要
- `battleMutters`・`weakness.hint`の仕組み → グリッド戦闘の文脈でどう活かすか要検討

## 未決定・要検討事項まとめ

- リーチ武器の具体的な射程ルール
- 同行者AIの移動・行動選択(Combat v1置き換えに伴う再設計)
- 大型モンスターのマルチセル占有ルール(移動・隣接・包囲判定)
- キャラ/モンスターのビルボード vs 3Dモデル(コンセプトデザイン確認後に決定)
- 外壁四隅の継ぎ目処理(重ねるか、角を斜めにカットするか)
- 包囲ボーナス倍率のバランス調整(現在の数値は仮置き)
