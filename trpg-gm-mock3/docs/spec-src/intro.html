坑道の向こう

ブラウザー試作「坑道の向こう」を、ソースを見ずに作り直せるように書いた仕様です。画像・立体モデルの素材は別に渡します。それ以外のルール、AIへの指示文、画面、立体舞台、固定データは全部ここに書いてあります。

  • 正本は試作のコードです。この仕様書は 2026-11-09 時点の trpg-gm-mock3/prototype/ を読んで書きました。数値と文面はコードから取り出したもので、推測で補った箇所は「不明」「未確認」と書いてあります。
  • 引用の書き方: S:149 は「scenario.js の149行目」という意味です。1行に多くの文が詰まったファイルなので、行番号に加えて関数名や文面を添えています。略記は章ごとに冒頭で定めています(D章だけ S が stage.js を指します)。ソースが無くても仕様は読めます。引用は、試作と照合したい人向けです。
  • 節番号には章の記号が付いています(例: A-7.2 は「ルールの章の7.2節」)。
  • 原文と書いてあるブロック(AIへの指示文、固定の文言、E章のデータと定型文)は、スクリプトでソースから機械的に取り出したものです。一字一句そのまま使ってください。

1. 作るもの

4人パーティの協力型ファンタジーTRPGの単発シナリオです。人間の参加者は1人(既定はイネス)で、残りの3人(ブロム・ガレス・マレン)はAIが演じます。坑道入口・排水室・石扉の広間を探索し、扉を開けて「灯りの番人」と戦います。結末は勝利か全員撤退の2つです。

遊びの中心は、仲間と相談してひとつの計画にまとめ、その結果を引き受けることです。判定はプログラムが行い、語りはAIが担います。ダイス、補正、成否、HP、所持品、場面の移動は、すべてルールのコードで決めます。AIの文章で状態を変えてはいけません。AIの返事が行動につながるのは、決まった形式を満たし、ゲーム側の再検査を通ったときだけです(B章)。

試作に無いもの(勝手に足さない): 複数端末の同期、音声通話、保存と再開、投票、犯人役、得点、灯石の最新仕様(MPの回復、灯石の光でだけ見える手がかり)、3通りの結末。

完成の条件: F章の検査がすべて通ること、E-3の再生ケースが同じ結果になること、2章の写真と同じ配置になること。

幅1440×900で撮りました。状態はスクリプトで切り替えています(AIは未接続)。冒頭の仲間3人の発言は、AIを使わずに出る固定の紹介文です。

  • 状態は1つのオブジェクト(state)だけです。初期値は E-2 のとおりで、描画は state を読むだけです。表示のために state を書き換えてはいけません。
  • 判定の結果は写しに適用します。戦闘の判定は structuredClone(state) に対して行い、終わってから state に代入します。
  • 古いAI応答は捨てます。再開始のたびに generation を1増やします。AIの応答が届いたとき、呼んだ時点の世代や state と違っていれば、何も表示せずに捨てます。
  • AIの既定: モデルは claude-haiku-5-5 で、プレビューサーバーが環境変数 MOCK3_LLM_MODEL で決めます。ブラウザー側のタイムアウトは45秒です。中継(mock2のserver.cjs)には「claude で始まらない名前は claude-haiku-4-5 に置き換える」という決まりがあります。既定の名前は claude で始まるので、この置き換えは起きません。設定画面の選択欄に最初に出る「Claude Haiku 4.5」は古いラベルで、モデル情報を受け取った時点で実際の名前に書き換わります。詳しくはB章の1節にあります。
  • 勝利の文は2つあり、出る場所が違います。判定の結果としてGMの記録に出る文は「胸の枠が外れた。心石を戻すと、番人は静かになった。」です。結末の画面で行動欄に出る文は「胸の枠が外れた。心石を戻すと、番人はランタンを掲げ、坑道の灯りが戻った。」です。両方とも出します。
  • 人物の内部IDと表示名: 魔法使いの内部IDは lydia で、表示名はマレンです。保存やAI応答の約束ごとはIDで扱うので、IDは変えないでください。AIに送るたびにIDと呼び名の対応を添えます(B章)。

scenario-parity が落ちる理由: 旧版と中身が違う関数は次の4つです。どれも意図した変更で、比べる元が更新されていません。

関数の中身の比較で止まるので、その後にある振る舞いの比較は一度も実行されていません。そこでも差が出るかは分かっていません。

コードを読み、実際に動かして見つけた挙動です。意図したものかどうかはコードから判断できません。作り直すときは試作と同じ挙動を基準にし、直すかどうかは作者が決めます。

#挙動確認方法
1点灯中のランタンを渡すと、lit=true のまま受け取った側は未装備になり、装備するまで消せないVMで実行
