# 先方プラットフォームと mock3 の対応(2026-11-06)

[CLIENT_PLATFORM.md](CLIENT_PLATFORM.md)(先方資料)と、mock3 の仕様・現行コードを突き合わせた。
「事実」はコードと資料で確かめたこと、「提案」はClaudeの案(採否は作者)。

## 1. 遊び方の6段階との対応(事実)

| # | 先方の段階 | mock3 の今 | 状態 |
|---|---|---|---|
| 1 | 配役: キャラクターと資料を受け取る | 4人は固定。人間の操作役は `CONTROL`(engine/core.js:3)でイネスに固定。選ぶ画面は無い。キャラクターと配役を分ける決定はあるが未実装 | 一部 |
| 2 | 導入: 世界観と事件の概要、自己紹介 | GMの導入と、仲間の持ち物紹介がある | あり |
| 3 | 調査: 証拠カードを入手し手がかりを集める | 見つけた本人だけが知る手がかり(`CLUES`)と、会話での共有がある。カードの形ではない | あり(形が違う) |
| 4 | 議論・密談: 全体の話し合い、1対1の交渉 | 宛先を選んで話せる。相手はAIだけで、人間どうしの密談は無い | 一部 |
| 5 | 投票: 犯人だと思う人物を指名 | 無い。近いのは戦闘の全員了承と、ランタンの合意 | 無し |
| 6 | エンディング: 真相が明かされ、GMが解説 | 勝利(心石を戻す)と全員撤退の2通り。真相の解説は無い | 一部 |

## 2. TRPGとの「異なる点」のどちら側にいるか(事実)

| 項目 | mock3 の位置 |
|---|---|
| プレイヤー同士の関係 | TRPG側(協力)。対立は無い |
| 情報の扱い | 中間。手がかりは本人だけが知り、共有するかは本人次第 |
| GMの役割 | TRPG側。判定はプログラム、即興の語りと発言の解釈はAI |
| 判定の仕組み | TRPG側(D20) |
| 結末 | 用意された1本の道(真相への推理は無い) |
| 継続性 | キャラクターを持ち越す設計だけあり、未実装 |

## 3. プラットフォームの機能との関係(事実)

- 募集・通話・テキスト・感想トーク: プラットフォーム側の機能。mock3 は持たない。通話は Agora RTC で提供される前提。
- ゲームの自動進行: mock3 はAIが進行と語りを担う。
- 手がかりの表示: mock3 の発見・シートの表示にあたる。
- 得点計算: mock3 に得点は無い(コードに該当なし)。

## 4. 先方資料の中の食い違い(事実)

- 4節「GM(進行役)は人が担当」と、6節「アプリがGMの役割を担い、ゲームを進める」。
- 7.2節の「用意された進行に沿って場を回す」を読む限り、アプリが担うのは手順の進行で、TRPGの即興の裁定は含まれていないと読める(解釈。先方に未確認)。

## 5. 先方に確かめたいこと

1. GMは人か、アプリか、シナリオごとに選べるのか
2. ゲーム中に判定役のサーバーを置けるか。ブラウザーと Agora だけで完結させるのか
3. AIを呼ぶ場所(Laravel か別のサーバーか)と、その費用を誰が持つか
4. プラットフォームに載るゲームに、得点・投票は必須か
5. 同じキャラクターで続けて遊ぶ仕組み(キャラクターの保存)をプラットフォーム側で持てるか

## 6. 提案(Claude、未決)

- mock3 の売りは、先方資料の「異なる点」のうちTRPG側の3つと言える: 即興で裁定するGM(AI)、ダイスの判定、続けて遊べるキャラクター。とくに「同じシナリオは1回きり」という先方のゲームの制約に対し、キャラクターを持ち越せる点は商品性の材料になる。
- 先方の利用者に寄せるなら、犯人は置かずに「推理で真相を答える」場面を足す案(手がかりを持ち寄って最後に答える)が、今のコードの資産を一番使える。6段階の「5 投票」の代わりに「真相の回答」を置く形になる。
- どの案も、人間4人の試遊で比べるまで決めない。
