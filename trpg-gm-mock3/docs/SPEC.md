## 1. 企画の芯

### 1.1 何を作るか
- 4〜5人がネット越しに声で遊ぶ、協力型ファンタジーTRPG。GMはAI。1回90〜120分。
- 最初に届けたい面白さは **仲間との連携** と **純粋な意味でのロールプレイ**。事前設定を大量に読まないと面白さに届かない、という既存ジャンルの入口の重さを減らす。
- 遊びの芯: **不確かな状況で、仲間と相談して1つの計画にまとめ、宣言して、結果を引き受ける。** 秘密や演技はこの芯に乗る味付け。
- 参加者は気持ちよくキャラクターになりきり、自由な台詞と仲間の応答で物語を進める。AIは演者を助ける下書き係。シーンは役者が演じる舞台そのもの(2026-10-05、作者)。

### 1.2 成り立たせる4条件(企画書 第1章)
| 条件 | 状態(企画上) |
|---|---|
| (1) 相談が要る決定がある | 先行例で言い切れる |
| (2) その人にしかできないことがある | 先行例で言い切れる |
| (3) 出番が回ってくる | 定番の考え方。数字は無い |
| (4) 情報が全員に同じようには見えない(秘密ではなく、各自が別のものを見ている) | 仮説 |

### 1.3 遊びの輪
```
全員で状況を見る → 各自が「自分にできること」を出す → 相談して1つの計画にまとめる
 → 宣言してダイスを振る → プログラムが裁き、AIが語り、世界が変わる → 次の状況へ
```
探索(各自が自由に動き、場面の移動だけ全員で決める)と戦闘(全員の行動をそろえて実行)の2つの速さで回す。

### 1.4 AIに任せること・任せないこと(決定)
- **判定はプログラム、語りはAI。** 成否・ダメージ・状態はJSが決める。LLMの返答で状態を直接書き換えない。
- AIに任せるのは、自由な発言の解釈、語り、仲間AIの台詞、人物設定の照合、合意の整理、台詞の下書き。
- AIの返答は「発言+行動案(JSON)」。ゲーム側が条件を検査してから実行する。

### 1.5 まだ分からないこと(企画書 1.8)
1. 複数人が声で話す場にAI GMを入れて回るか
2. 情報の偏りが楽しさにつながるか
3. 声を文字にしてGMに渡す仕組みが実用になるか

## 4. シナリオ「坑道の向こう」の流れ

場面は3つ: 坑道入口(`entry`)、石扉の広間(`hall`)、排水室(`drain`)。入口は屋外で雨と雷光、坑道内では止まる。

1. **導入:** GMが紹介を促し、仲間が持ち物を1〜2品ずつ名乗る(`OPENING_ITEMS`、AIを使わない定型)。
2. **入口(暗い):** マレンがランタンを灯すと台車・レール・通路が見える。台車を調べると鉄の工具が見つかり、イネスが拾う。
3. **隠し要素(任意):** 壁の傷 → マレンが解読「灯を伏せよ。蒼き塵は、隠された場所へ帰る」→ ランタンを消すと蒼白い塵 → 隠し収納 → ガレスがD20で解錠 → 灯石。
4. **排水室:** 操作輪をブロムが支え、イネスが工具で引っ掛かりを外して排水する。
5. **広間(再訪で変化):** 排水後は石扉の水圧が消えている。ガレスが鍵を外し、ブロムが支え、イネスが工具で固定するか隙間に入って留め具を外すと開く。金槌で壊すと開くが、番人が身構える(HP30)。
6. **番人戦:** 「石扉の奥へ進もう」で開始。
7. **結末:** 番人のHPが0 → 「心石を戻すと、番人は静かになった」(`outcome='win'`)。全員が撤退を選ぶ → 撤退(`outcome='retreat'`)。

## 5. 機能仕様

### 5.1 会話と依頼→実行
- 相談と実行依頼は同じ入力欄。宛先は「全員/各人/GM」を選ぶ。Enterで送信、Shift+Enterで改行。
- 質問・仮定・否定・過去形は実行しない。明示した依頼と、直前の一意な申し出への短い了承(「お願い」など)だけを実行する。短い了承は一番新しい申し出への返事として扱う。
- 観察・解読の明示依頼は、ゲーム側がその場で実行し、仲間が結果を報告する(AI呼び出し1回)。仕掛け操作・戦闘・受け渡しは本人の了承を挟む。
- 不得意な依頼には、本人が理由を述べて代わりの協力を申し出る。仲間AIからの依頼・ツッコミもある。
- 暗い場所での調査依頼には、GMが先に「灯してもらいましょう」と返す。
- **撤回:** 「自由文は相談のみ」「仕掛け操作は明示依頼だけ」は上記に更新。
- **未実装として残す範囲:** 任意の自由行動の裁定、汎用の意図分類、全会話の永続記録、長期記憶。

### 5.2 合意(相談)
- エンジンの汎用の仕組み(`consents`、`settleConsent` ほか)と、章ごとの議題定義(`CONSENT_TOPICS`)に分けた(2026-10-07、作者決定)。今の議題はランタンの点灯・消灯だけ。
- GMが会話から依頼・反対・疑問・撤回を整理する。反対・疑問・相反する案が無く、持ち主以外の依頼があるときだけ、持ち主本人が了承か保留を判断して実行する。多数の賛成で反対を消さない。
- 本人が今できない操作の自己依頼は相談に残さない(2026-10-07、試遊の停止対策)。
- 冗談を混ぜる割合 `CHAT_JOKE_RATE=0.2`。
- **未決:** ランタン以外の探索行動をどこまで自発実行させるか。

### 5.3 探索と発見
- **決定:** 探索中は各自が自由に考え、個別に実行できる。発見は働きかけに確実に反応する。危険な挑戦はダイスで判定する。
- **撤回:** 探索の順番制、「最初から見えている対象を順に調べる」方式 → 発見型へ。
- 発見済みの地点は光点と短い名前で示し、選んだときだけ操作を出す。手がかりは見つけた本人だけが知り、会話で共有する。
- 収納の解錠: D20+3(ガレス)+2(イネスの支援)。10以上で静かに成功、5〜9で成功するが音が響く(番人が警戒)、4以下は失敗で再挑戦+2。
- ダイスの色: イネス青緑、ブロム琥珀、ガレス紫、マレン青、GM赤。
- **未決:** 発見を個人に届けるか全員に届けるか、報酬の量、罠・解錠・破壊のコスト。

### 5.4 所有・装備・受け渡し
- **決定:** 共有アイテムは無い。すべて個人の所有。受け渡しは「誠意を伝える遊び」として扱う。
- `owner`(所有者)と `holder`(今持っている人)を分ける。譲渡は両方、貸与は holder だけ変わり、返却は貸主へ。又貸し不可。手放すと、その道具を使う能力も使えない。直近12件の受け渡し履歴を会話へ渡す。
- **装備(2026-10-08):** 所持と装備は別。装備は本人が決め、他の仲間は頼むだけ。装備していない品を使う行動は候補に出ない。
- **開始時の装備:** ランタンだけ装備(未点灯)。杖・金槌・盾・片手剣は未装備(人物は素体で立つ)。ランタンと杖は同じ手を使うので同時に持てず、点灯したランタンを外すと消える。杖が無いと火球・石つぶては使えない。
- ガレスの片手剣(内部ID `dagger`)は剣と鞘で1品。素手・納刀・抜刀の3つの姿があり、抜刀・納刀は手動でも切り替えられる(見た目だけで判定は変えない)。
- 拾う品: 鉄の工具(排水と扉の固定の2用途)、灯石。
- **未実装として残す範囲:** 同じ品の複数個、好感度の数値、受け渡しのアニメーション、AI同士の自発的な受け渡し。

### 5.5 地図と移動
- **決定(2026-10-05):** 地図はマレンの「古い坑道の地図」1枚(イネスの坑道図は外した)。
- 「通路が見える」「地図に記載がある」「訪れた」を区別する。未知の出口は「奥へ続く通路」「下りの通路」。訪問済みは実線、記載だけは点線。
- 地図は持ち主に頼んで見せてもらう。行き先が会話から一意に決まれば全員で移動する。
- **未決:** 不正確な地図や、地図を書き足すゲーム性。

### 5.6 戦闘
- **決定:** 見せ場は強敵との連携戦。役割ごとに2〜3個の行動から選び、順番を参加者どうしで相談する。位置は前衛・後衛の2列。mock2のアイソメトリック盤面は採らない。
- **撤回:** 「盤面なしで宣言・判定・手助けだけ」→ 2列。
- 本人が自分の行動を選び、AI3人の了承と支援の順番がそろったら実行する。不正な行動を出したAIには1回だけ選び直させる。
- 各人の行動: イネス=見抜く/手助け/投げ縄、ブロム=かばう/金槌で打つ、ガレス=急所を狙う、マレン=火球(残り回数あり)/石つぶて。全員に「退路を確保する(撤退希望)」。
- 数値(`BATTLE_RULES`): 目標値10。見抜く・弱点・支援後の攻撃に各+5。威力 火球6/石つぶて2/弱点への急所8/急所3/金槌4/投げ縄3。反撃 前衛の薙ぎ払い4、かばう本人6、魔法使いへの光線5。撤退希望者への反撃は半減(切り上げ)。
- 番人は行動を予告する。偶数ラウンドは魔法使いへの光線で、かばうは選べない(2026-10-08)。
- 撤退ルールはCodexが裁量で入れた暫定。
- **未実装:** リアルタイム戦闘、射程、撤退時の別シーン。

### 5.7 人物設定の開示とGM照合
- 自分のシートは全設定を表示。他人の設定は、会話で確認できた項目だけ表示する。
- 別のGM呼び出しが、発言の中身を正本の値・引用と照合する。矛盾は1回言い直させ、2回目で保留。人間の誤った自己申告はGMが訂正する。
- **未実装:** 設定の保存・編集UI。

### 5.8 灯石(2026-10-07〜08、作者決定)
- 青い塵が集まった石。タイトルの「儚きもの」の象徴で、魔法の源泉。
- **照らす:** 消えない。何度でも使える。**MP回復:** 使うと塵に還って消える。最後の戦闘で「ここで使うか」を選ばせる。
- 灯石の光でしか見えない手がかりを置く。ただし進行に必須にしない(得をするだけ)。
- 入手した瞬間、マレンが熱く解説する(塵の石・魔法の源泉・照らせる・MPを戻せるが塵に還る・手がかりの在りか)。
- 塵の意味付けは素粒子(弱い力・ニュートリノ)の概念を下敷きにする。画面や台詞に物理の用語は出さない。
- MP回復は、火球の残り回数 `state.fire` を戻す形が最小(新しい数値を足さない)。
- **未決:** 手がかりの置き場所と得られるもの(仮案: 石扉に番人の弱点 / 排水室の壁に近道)、MP回復を誰がいつ使えるか、mock2の「灯石」との名前の重複。
- **将来(今は作らない):** 強化・合成・MP抽出。

### 5.9 画面(A案、2026-10-04 作者了承)

### 5.10 2.5D舞台・照明・カメラ
- Three.js 0.185.1(`prototype/vendor/`)の透視投影に、背景の板(カキワリ)とスタンディを立てる。方針は「3DCGらしくない、作り物の手触り」。
- 首振り左右20°、縦の視野角65°、消失点は上端から54%、前後幅2.6。人物は手前から4列(front/middle/back/farthest)、中央へ最大12°内向き。身長に比例した高さ。
- 背景は左右各18%を25°折り返す(`?background=flat` で平面)。左右のカメラ操作は位置を変えず向きだけ変える。
- 場面転換: 全員が後ろを向く(0.45秒)→ 背景の板が3秒で回る → 話した人だけ正面に戻る。戦闘・結末・動きを減らす設定・3D不可のときは暗転。
- 発言者へのピンスポット(琥珀、明るさ70%、発言後7秒で消える)。ゲーム内の灯りとは別。
- 床は描いた絵+明るさから作ったノーマルマップ。光源はマレンのランタン。
- 戦闘は探索と同じカメラとスタンディで、パーティが敵と向き合う。敵が左右に動いても立ち位置は保ち、向きだけ追う。
- **撤回:** 背景1枚+人物の縮小による奥行き、円盤の廻り舞台、黒子、装備を台座の札で見せる案。
- **未決:** 層の分割・袖・幕などの演出案、戦闘カメラの候補、空の板(雷鳴の場面)。
