きっかけ: 実プレイで見つけた2件のシナリオ不具合を、TASではなく直感的に直せる仕組みを考えたい。
TASが現時点で使いづらいという前提から始めたが、調べた結果、問題はエディタの使い勝手の**手前**にあった。

## 検証済みの事実(測定・コード確認済み)

| 場所 | サイズ | 更新 |

| `TAS/data/chapter_01.json` | 20529 | 8/7 16:35 |
| `trpg-gamebook/data/chapter_01.json` | 18696 | 8/12 16:39 |

| `trpg-gm-mock2/public/data/campaigns/lanternhill/` | 22020 | 8/18 10:03 |

**同期するコードは1つも無い。** npm script・シェル・フック・サーバー処理を全探索して不在を確認した。
さらにドキュメントは同期を**禁止**している(`trpg-gamebook/CLAUDE.md:30`、`SPEC_editor_v1.md:20`、
`SPEC_playlog_review_v1.md:201`)。つまり分岐は事故ではなく方針の結果である。

### 2. 今日の2件は、種類が違う

| 件 | 症状 | 分布 |
|---|---|---|
| シーン3 `greeting`「木柵を壊したけど、問題ないかな？」 | プレイヤーの台詞がNPCの口に入っている | **mock2のコピーのみ**。他4つは空 |
| シーン2 `blockedText`「左の坑道は崩れて行き止まりだ」 | 蝙蝠遭遇の前提(s2c開示)を潰す案内文 | **5箇所すべて** |

前者はコピー間のずれ、後者は作り込みの問題。エンジンは `if (node.npc && node.greeting)` で
判定するため、`greeting`が空の4コピーでは第一声は出ない。
ただし`npc`は5コピーすべてに在り、`npcAgentReply`は`sc.npc`の存在だけで毎ターン動くので、
**「番人が喋る」自体は全コピーで起きる**。`greeting`を空にしても止まらない。

### 3. TASにはシーン直下の `blockedText` を編集する欄が無い

- TASの`blockedText`入力は**出口ごと**の1種類だけ(`条件未達時の説明`、`js/02-exit-editor-simple.js:18`)
- シーン直下の`node.blockedText`は、読み込んだデータから出力時に素通しされるだけ(`js/01i-output.js:89`)
- **今日の2件目は、TASでは直せない**

### 4. TAS→mock2の配達経路は既にあり、質も高い

`出力確認`タブ → `mock側へ出力` → POST `/api/export-campaign`(`TAS/server.cjs`)

- `campaigns/<id>/campaign.json` と `chapter_01.json` を書く
- **`campaigns.json`の索引も更新する**(`chapters[].file`、`defaultChapter`を突き合わせ)
- 書いた後に mock2 の `progression.test.mjs` と `playthrough.test.mjs` を実行し、`NG`行を警告として返す

配達と検証という難しい部分は既に動いている。

### 5. gamebookには理想的な修正ループが既にあり、テストも通る

`trpg-gamebook`、2026-08-14実装(`docs/SPEC_playlog_review_v1.md`)

```
1. 遊ぶ  2. 記録を書き出す  3. 記録に「」で注文を書き込む
4. 「遊んだ記録を読み込む」← 新しい手はこれ1つ  5. 提案カードを採用
```

- パーサを書かずAIに解釈させる。7周分13件の注文を数え「10件は文字列書き換えで足りる」と実測した上で設計
- `FIX_FIELDS`のホワイトリストで書き換え先を限定。照合キー(`entity`/`aliases`/`match`/`triggerTerms`)は拒否
- `test/playlog.test.mjs` 8項目すべて通過(照合キー拒否、存在しない場面の拒否も検査済み)
- **シーン直下の`blockedText`と`greeting`は書き換え対象に入っている** — 今日の2件目はここで直せる

### 6. どちらのツールも、追跡されるファイルを書かない

- TASの`保存` = `<campaignName>.json` の**ブラウザblobダウンロード**。`TAS/data/`は読み取り専用
- gamebookのエディタ = localStorageの下書き。ファイルへの唯一の経路は`.json`を書き出すの**blobダウンロード**
- `chapter/` はその成れの果て。gamebookエディタからの連続ダウンロード6個
  (`chapter_01 (1)`〜`(5)`、8/13の90分間、(3)(4)(5)はサイズ同一 = 変化なしの重複押し)。
  未追跡、コードからの参照ゼロ

**5つに分かれた根本原因はここ。** どのツールもgitが追う場所に書かないため、
編集はlocalStorageとDownloadsフォルダに溜まり、正本が育たない。

## 診断

2つのオーサリングツールが、**互いに欠けているものを持っている**。

| | 修正ループ | 配達 |
|---|---|---|
| TAS | シーン直下`blockedText`の欄が無い | **あり**(campaigns.json更新 + テスト実行) |
| gamebook | **あり**(記録に「」→AI提案→採用、テスト付き) | 無い(blobダウンロード) |

作者が感じている「直した実感がない」は、エディタのUIの問題ではなく、
**編集がどこにも着地しない**ことの症状である。

したがって、新しいエディタを作るのは筋が悪い。**既にある2つの半分を繋ぐ**のが最短である。

## 分岐する論点(未決 — ここが決まらないと設計が定まらない)

### 論点: 章データの正本を1つに決めるか。決めるならどれか。

**案A: `TAS/data/` を追跡される正本にし、TASのサーバーに「正本へ書き戻す」経路を足す**
- 根拠: TASのサーバーは既にファイルを書ける。今はmock2にだけ書いている。書き先を1つ増やすのは小さい
- 得: 動いている配達経路(campaigns.json索引 + テスト実行)をそのまま使える。ここが一番作り直したくない部分
- 代償: TASにシーン直下`blockedText`の編集欄を足すか、UIを介さずgamebookの修正リストを受け取る口を作る必要がある

**案B: mock2のコピーを正本にする**
- 得: 実際に遊ぶファイルがそのまま正本。コピーが1つ減る。TASは既にここへ書いている
- 代償: `trpg-gamebook/CLAUDE.md:30`の明文化された方針(mock2のJSONを編集・上書きしない)と正面から衝突するため、方針の書き換えが要る
- **未検証のリスク**: TASの読込→出力の往復で、TASが編集対象にしていないフィールドが落ちないか。
  素通し実装(`01i-output.js:89`)なので保たれる見込みだが、測っていない。
  正本をTASの往復に載せる前に、ここは必ず測る

**案C: 5つのコピーを維持し、差分レビュー付きの同期コマンドを足す**
- 得: どのツールの方針も変えない
- 代償: 5方向のマージを永久に抱える。今日の`greeting`のずれは再発する

**推し: 案A。** 理由は、今日いちばん時間を食ったのが「どのファイルの話をしているか」の突き合わせであり、
UIではなかったこと。そして配達と検証という難しい部分がTAS側で既に完成していること。
