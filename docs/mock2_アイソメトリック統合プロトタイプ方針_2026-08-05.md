# mock2 アイソメトリック統合プロトタイプ方針

## 概要

現行mock2の2D物語画面と別画面のアイソメトリック戦闘を、常設の3D舞台へ統合する試作方針を整理した。既存mock2は保全し、独立した新規プロジェクトで検証する。

## 決定事項

- 新規プロジェクトは`/Users/yasuda_k/Desktop/Terminus/trpg-gm-isometric`とする。現行mock2のGit管理済みファイルを基点にした独立Gitリポジトリであり、元リポジトリへのremoteは設定しない。
- 探索・会話・戦闘は同じシーンMAPを使う。戦闘開始時に別MAPや別画面へ遷移せず、グリッド・戦術UI・カメラを切り替える。
- 人物・敵はローポリの3Dフィギュアを正本とし、戦闘駒と会話時の寄りを同一モデルから表示する。
- カメラは、舞台全景、到着時の主観、会話の寄り、戦術アイソメを固定ショットとして使う。自由なカメラ操作を前提にしない。
- 同行者がCPUのときは、重要な行動で短い視点演出を使える。人間同行者の画面は強制せず、各クライアントが演出を選べるようにする。
- シーンMAPは少数の固定テンプレートを回転して組む。作者は座標を直接入力せず、`blocker`、`blocked-route`、`ambient-clue`、`ambush`等の意味的な配置役割を指定する。
- 最初の縦切りはシーン2「分かれ道」とする。木柵、左の崩落、油の匂い、錆喰いの待ち伏せを同一MAPへ配置し、会話→調査→敵出現→戦闘→会話復帰を確認する。

## 現在の状態

- `trpg-gm-isometric`を作成し、初期コミット`cb377f7`とブランチ`codex/isometric-stage`を作成した。
- 現行mock2の進行エンジン、シナリオJSON、Three.js戦闘コア、既存画像をコピーした。
- `node_modules`と`dist`はコピーせず、新規プロジェクトで`npm ci`を実行した。
- `npm run test`は全件通過し、`npm run build`も成功した。Viteは既存の大きなJSチャンクについて警告する。
- 現在の戦闘MAPはランダム生成で物語シーンから独立している。新規プロジェクトではこれを固定シーンMAPへ置き換える予定である。

## 未解決事項

- 分岐MAPのパーツを1マス単位にするか、3×3または3×4の部屋・通路モジュールにするか。
- 会話時の顔の感情を、視線・ライティング・カメラだけで始めるか、表情差分まで作るか。
- 人間同行者を実際に接続するための通信・同期方式は未設計。
- モバイル実機での3D舞台、人物、カメラ切替の性能は未計測。

## 次に行う作業

1. 分かれ道の固定MAPと意味的配置アンカーを定義する。
2. 同一MAPを探索表示と戦術表示で切り替える最小実装を作る。
3. 会話寄り、到着主観、戦術アイソメのカメラ3種を実装する。
4. 木柵の調査と錆喰いの待ち伏せを、既存シナリオ状態に連動させる。
