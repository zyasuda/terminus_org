# ADR-0001: アイソメトリック常設舞台の独立試作

## Status

Accepted

## Date

2026-08-05

## Context

### Problem Statement

現行mock2は、2D背景・立ち絵の物語画面と、別ルートのアイソメトリック戦闘画面に分かれている。会話、到着、待ち伏せ、戦闘を同一の3D舞台で連続させる試作を行う。

### Constraints

- 現行mock2は変更しない。
- 進行エンジン、シナリオデータ、決定論的な戦闘コアは再利用する。
- スマートフォンで扱える軽量な低ポリゴン表現にする。
- 自由な自然言語による調査を、3D座標入力に置き換えない。

### Requirements

- 探索・会話・戦闘で同一のシーンMAPを使う。
- 会話の寄り、到着時の主観、戦術用アイソメを切り替えられる。
- 戦闘開始時に地形や人物位置を再生成しない。

## Decision

`trpg-gm-isometric`を現行mock2から独立した新規Gitリポジトリとして作成し、常設Three.js舞台を試作する。

最初の縦切りは「分かれ道」とする。固定テンプレートMAPに木柵、崩落、油の匂い、待ち伏せを配置し、会話・調査・戦闘・会話復帰を同一MAP上で確認する。

シーン作者は座標を直接指定せず、`blocker`、`blocked-route`、`ambient-clue`、`ambush`などの意味的な配置役割を指定する。テンプレートが役割をマス、モデル、カメラ注視点へ解決する。

### Architecture Diagram

```text
進行エンジン ── シーン状態・調査結果 ──┐
                                        ├─ 常設3D舞台 ── 会話/到着/戦闘カメラ
戦闘コア ── 位置・行動・結果 ───────────┘
```

### Key Interfaces

- シーン: `layout`、入口、対象の意味的配置役割を持つ。
- 舞台: 同一MAPを探索表示と戦術表示で使い分ける。
- 戦闘: 現在のランダム生成盤面ではなく、シーンMAPと配置済みユニットを受け取る。

## Alternatives Considered

### Alternative 1: 現行mock2を直接改修する

- **Pros**: ファイルの重複がない。
- **Cons**: 現行版を壊しやすく、2D版との比較ができない。
- **Rejection Reason**: 表示構造の変更範囲が大きい。

### Alternative 2: 戦闘画面だけを別画面のまま強化する

- **Pros**: 実装量が少ない。
- **Cons**: 会話・到着・待ち伏せの連続性を得られない。
- **Rejection Reason**: 今回の体験目標を満たさない。

## Consequences

### Positive

- 現行mock2を保全したまま比較できる。
- 人物モデル、会話カメラ、戦闘駒を同じアセット契約で制作できる。

### Negative

- 新規プロジェクト側で依存管理とテストを維持する必要がある。
- シーンごとの空間テンプレートとカメラ安全域を制作する必要がある。

### Risks

- カメラ演出が戦闘テンポを阻害する。短い演出とスキップを基本にする。
- 画面上の対象と物語の調査対象が食い違う。重要物は`secret.id`と配置を直接結ぶ。
- 人間同行者の画面を強制すると操作を妨げる。視点演出は各クライアントの任意表示にする。

## Performance Implications

- **CPU**: 低ポリモデルと固定MAPで抑える。
- **Memory**: シーン単位で必要なモデルだけを読み込む。
- **Load Time**: 最初の縦切りで実機計測する。
- **Network**: 現段階では追加通信を前提にしない。

## Migration Plan

1. 分かれ道の固定MAPとカメラモードを作る。
2. 既存シナリオの木柵・崩落・待ち伏せを配置する。
3. 同じMAPで戦闘コアを起動する。
4. 検証後、坑道入口、灯りの部屋、村、マイラの部屋へ広げる。

## Validation Criteria

- 分かれ道で、会話、調査、敵出現、戦闘、戦闘後の会話を画面遷移なしで通せる。
- `npm run test`と`npm run build`が通る。
- モバイル実機でカメラ切替と戦闘操作を確認する。
