## Goal

**作者が編集するたびに、機械が「言葉が繋がっているか」と「どこで分かれたか」を答える。**

作者は新しい画面を1つも覚えない。答えは既にある右の「検査」欄に出る。既に編集の0.4秒後に自動で走っている（`src/editor.js:25` の `later()`）。**そこに項目を足すだけ**で、「頻繁に」を満たす。

## 最優先の原則

- **作者が触る場所を増やさない。** 新しい画面・新しいタブ・新しいボタンを作らない
- **作者にIDを見せない。** 内部の識別子は画面に出さない
- **AIを呼ばない。** この仕様の検査は全部ローカルの純関数で行う。通信ゼロ・課金ゼロ・答えが揺れない
- **既存の判定を再実装しない。** `progression.js`（書き換え禁止）と `inventory.js` の関数を呼ぶ
- **新しい項目は `warn` にする。** `error` にすると既存テスト「無傷の章は構造エラーなく完走できる」が壊れる。実際に現在の `data/chapter_01.json` で下記(a)(b)は検出される（これはデータの実際の欠陥であり、検査が正しく働いている証拠）

## 1. 画面からIDを消す

`src/editor.js:29` の `list()` が `item.entity || item.label || item.id || "名称なし"` の順に落ちるため、**行き先が `to_scean02`、遭遇が `encounter_1` と表示されている**（実測済み）。

- **行き先**: 行き先の場面名を出す。`exit.to` から解決する（`"ending"` はエンディングの名前、`scene:N` / 数値は該当シーンの `name`）。解決できなければ `行き先が未設定`
- **遭遇**: `encounter.enemy?.name` を出す。空なら `名前のない遭遇`
- **調べられるもの**: `entity`（現状のまま）
- **`item.id` へのフォールバックを消す。** IDが画面に出る経路を残さない

`list()` は種類を受け取っているので、種類ごとの表示名を作る小さな関数を1つ足して差し替えること。**`list()` を4つに分裂させない。**

完了条件: エディタの一覧にIDが1つも出ない。

## 2. 語句の統一チェック

`src/validate.js` に `vocabularyFor(chapter)` を足し、`inspect()` の `structure` に混ぜる（`structureFor` の結果に連結する）。既存の `issue(level, where, message)` をそのまま使う。**全部 `warn`。**

### (a) 本文で示した語に、反応するものが無い

**集める語**（場面ごと）:
- `brief` の中で `「」` または `『』` で囲まれた語
- `hintChips[]` の各要素

**反応する語**（同じ場面）:
- `secrets[]` の `entity`、`aliases[]`、`trigger`
- `exits[]` の `match[]`
- `encounters[]` の `triggerTerms[]`

**判定**: 示した語が、反応する語のどれとも「完全一致しない」かつ「どちらか一方が他方を含む関係にもない」なら警告。

メッセージ: `導入文の「見取り図」に反応するものが無い` / `hintChipsの「金属音」に反応するものが無い`

**実測（実装前の現状）**: イントロの `brief` に `「坑道」「見取り図」「金属音」` があり、`hintChips` は `["見取り図","金属音"]`。**イントロには `secrets` が1件も無いため、3語すべてが警告になる。** これが期待される出力である。

### (b) 入手できるが、使い道が無いアイテム

**入手できる語**:
- `exits[].addItems[]`
- `loot[].name`
- `chapter.startingInventory[]`（文字列の配列。要素がオブジェクトなら `name`）

**使い道のある語**: 実際にアイテムを参照する箇所だけを数える。**推測で足さないこと。** `src/gamebook.js` と `src/progression.js` と `src/inventory.js` を読み、`has()` / `take()` / `weakness` / `requires` のうち**アイテム名を照合している経路を実コードで特定してから**列挙する。特定できた経路のみを対象にし、**特定できなかったものは対象に入れない**（誤検出を出さない）。

**判定**: 入手できるのに、どの経路からも参照されない語を警告。

メッセージ: `「回復薬」は入手できるが、使う手段が無い`

**実測（実装前の現状）**: `回復薬`（イントロ）、`心石の欠片`（シーン3）、`30ゴールド`（エンディング）、および `startingInventory` に混入している `player` / `member_2` が該当する。**後者2件はアイテムではなく人物のIDであり、データの誤りである。** 実装後にこれが警告として出ることを確認すること（データは直さない。検査が見つけたことを示すのが目的）。

### (c) 綴りの揺れ

場面をまたいで、**同じものが別の綴りで書かれていないか**。

**比較する語**: 各場面の `secrets[].entity`。

**正規化**: 助詞と記号を取り除く。取り除く文字は `の が を に は へ と`、および空白・中黒・ハイフン。

**判定**: 正規化後が一致し、かつ元の文字列が異なる組を警告。（例: 「木の札」と「木札」は正規化後どちらも `木札` で一致）

メッセージ: `「木の札」（シーン1）と「木札」（シーン2）は同じものですか`

**保守的に。** 編集距離や部分一致で広げないこと。誤検出は作者の集中を削る。正規化一致だけに限る。

**実測（実装前の現状）**: 現在の `data/chapter_01.json` では該当なし。テストは人工のデータで行うこと。

## 3. 分岐の可視化

`src/validate.js` の `play()` が、50回分の終わりの状態を**その場で捨てている**。残す。

各runの終了時に集める:
- 決断の選択: `state.flags` の `decision:<id>` の値（選択肢のid）。**選択肢の `label` に解決して人間の言葉にする**
- 倒した敵 / 逃がした敵: `state.defeated` / `state.fled`（**実際のフィールド名を `src/gamebook.js` で確認してから使うこと**）
- 死亡したか（`state.hp <= 0`）

これを「異なる結末」ごとに数え、`result.outcomes` に入れる。

```js
outcomes: [
  { label: "錆喰いを倒した", count: 31 },
  { label: "錆喰いを逃がした", count: 12 },
  { label: "木柵を調べ、安全な通路を探す を選んだ", count: 27 },
  ...
]
```

**形は `{ label, count }` の平らな配列**。件数の多い順。組み合わせの全パターンを出さない（50回では意味のある数にならない）。**個々の分岐点ごとに数える。**

`src/editor.js:104` の `paintInspection()` の「自動プレイ」ブロックの下に、`<h3>分岐</h3>` として `label` と `count` を並べる。**分岐が1件も無ければ、この見出しごと出さない。**
