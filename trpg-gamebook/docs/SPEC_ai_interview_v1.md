# AI取材 v1 仕様 — 場面の「調べられるもの」を会話で埋める

作業対象: `/Users/yasuda_k/Desktop/Terminus/trpg-gamebook`

## 最優先の原則

**作者が気持ちよく物語作りに集中できること。** この仕様のすべての判断はここから来ている。技術的に正しくても、作者の集中を切る作りは失敗とみなす。

具体的には、次を絶対に守る。

1. **作者に内部ID・条件式・照合仕様を見せない。** 見せるのは作者が「直したい」と言ったときだけ
2. **作者が書いた文章を、承認なしに上書き・破棄しない。** AIの提案は必ず採用／却下を選ばせる
3. **待ち時間を無言にしない。** 応答は流しながら出す
4. **AIが落ちても書く作業は止まらない。** AI層は常に追加であって関門ではない。キーが無くても、通信に失敗しても、既存のフォームはそのまま使える
5. **一度に大量の質問をしない。** 1つずつ聞く
6. **正しさは機械が見る。** 作者には「面白いか」だけを判断させる

## 範囲

**1つの場面の「調べられるもの」(`secrets[]`)を、会話で埋めるところだけ。** 行き先・決断・遭遇・複数章・章の新規作成はやらない。ここが成立してから同じ形で広げる。

## 1. APIキーとモデル

- キーは**画面の設定欄から作者が貼る**。`localStorage` の `gamebook:geminiKey` に置く。**コードにもリポジトリにも絶対に書かない**
- 設定欄には「入力した原稿はGoogleへ送られます」と1行で明示する。脅し文句にはしない
- **モデルIDをコードに直接書かない。** 起動時に `GET https://generativelanguage.googleapis.com/v1beta/models?key=<KEY>` でモデル一覧を取り、`generateContent` に対応するものだけを選択肢として出す。作者が選んだものを `gamebook:geminiModel` へ保存する
  - 理由: モデルIDは変わる。埋め込むと、ある日突然動かなくなる
  - 一覧が取れないときは、その旨を出して**フォーム編集へそのまま戻れる**ようにする。エラーで画面を止めない

## 2. 会話の形

場面を選ぶと、フォームの**上**に相談パネルが出る。ここが主役で、フォームは折りたたんでおく（§5）。

```
┌────────────────────────────────────────┐
│ AI  この場面には、何がありますか。         │
│     見えるもの、匂い、音、気配。         │
│     思いつくまま書いてください。          │
│                                        │
│ 作者 封鎖された木柵がある。古いのに崩れる  │
│     気配がない。あと油の匂いがする。      │
│                                        │
│ AI  木柵が「崩れない」のが気になります。   │
│     内側から誰かが手を入れている、という   │
│     ことでしょうか。                     │
│                                        │
│     ── こう書けそうです ──               │
│     ┌──────────────────────────────┐  │
│     │ 封鎖の木柵                     │  │
│     │ 呼び名: 柵、木柵、バリケード     │  │
│     │ 調べると: 内側から維持されている  │  │
│     │ 手がかりがある                  │  │
│     │          採用   直す   捨てる    │  │
│     └──────────────────────────────┘  │
│                                        │
│ [ここに書く                        ] 送る│
└────────────────────────────────────────┘
```

- **AIから話しかける。** 空欄を見せて待たない
- 提案は**カード**で出す。採用するまで章データには一切書き込まない
- **「直す」を押すと、そのカードの内容がフォームに入った状態で編集できる。** ここで初めて入力欄を見せる
- **却下しても、作者が書いた文章は消えない。** 会話に残る

## 3′. 実測で確定したGemini APIの契約（2026-08-12）— §3より優先する

**旧API（`v1beta/models/<id>:generateContent` / `:streamGenerateContent`）は、このキーでは使えない。** 会話向けの27モデル全部が404を返し、本文は「This model is no longer available to new users. ... use the Interactions API」だった。実測済み。

正しい呼び方は次のとおり。すべて実際に叩いて確認した。

```
POST https://generativelanguage.googleapis.com/v1/interactions
x-goog-api-key: <KEY>
Content-Type: application/json

{"model":"gemini-3.5-flash-lite","input":"…","stream":true,"store":false,
 "system_instruction":"…"}
```

- **バージョンは `v1`。** 公式ドキュメントには `v1beta2` と書いてあるが**404になる**。`v1` と `v1beta` が200
- `store:false` と `system_instruction` は受け付ける（確認済み）。`thinking_level` / `reasoning` / `instructions` は `Unknown parameter` で400
- **`store:false` を必ず付ける。** 既定は `true` で、作者の原稿がGoogle側に保存される

### 応答の読み方

**ストリーム（SSE）**: `data:` 行のJSONで、`delta.type === "text"` のものだけが本文。

```
event: step.delta
data: {"index":1,"delta":{"text":"あ","type":"text"},"event_type":"step.delta"}
```

`step.start` で `step.type === "thought"` が来る間は、モデルが考えている。**本文は出ないので、ここで画面を無言にしない**（後述）。

**非ストリーム**: `steps[]` のうち `type === "model_output"` の `content[].text`。

### モデル

一覧は従来どおり `GET /v1beta/models` で取れるが、**一覧に出るからといって使えるとは限らない**（上記のとおり大半が404）。実測で200を返したのは次の3つだけだった。

| モデル | 最初の文字が出るまで |
|---|---|
| **`gemini-3.5-flash-lite`** | **685ms** |
| `gemini-3.5-flash` | （未計測。200は確認） |
| `gemini-3.6-flash` | 5,290〜6,949ms |

**既定は `gemini-3.5-flash-lite` にする。** `gemini-3.6-flash` は最初の1文字までに5〜7秒かかり、その間ずっと無言になる。取材の相手としては遅すぎる。作者が設定で変えられるようにはしておく。

モデルIDはコードに直接書かない方針を維持する。ただし**既定として選ぶIDだけは書いてよい**（一覧に無ければ先頭の候補へ落ちる）。選んだモデルが404を返したら、「このモデルは今使えません。別のモデルを選んでください」と出して一覧へ戻す。**エラーで画面を止めない。**

### 考えている間を無言にしない

`step.start`（`type: "thought"`）を受け取った時点で、**「考えています」と分かる表示を出す**。本文の最初の文字が来たら消す。原則3はこれで満たす。

### 会話の続け方

Interactions APIには `previous_interaction_id` でサーバー側に履歴を持たせる仕組みがあるが、**使わない**。`store:false` と両立せず、作者の原稿をGoogle側に残すことになる。これまでの会話は**こちらで `input` に組み立てて渡す**。

## 3″. 既定モデルとバックアップ（2026-08-12、実測・公式価格で確定）— §3′より優先する

`GET /v1beta/models` の一覧33件のうち、`/v1/interactions` で実際に200を返したのは6件だけだった（`-preview`付きは全部404）。実測済み。

```
gemini-3.1-flash-lite   gemini-3.5-flash-lite   gemini-3.5-flash
gemini-3.6-flash        gemma-4-26b-a4b-it      gemma-4-31b-it
```

**モデル選択の一覧には、この6件だけを出す。** 一覧に出るものすべてを選択肢にしない（残り27件は選んでも404になるだけで、作者に失敗を体験させる）。

### 既定モデル: `gemini-3.1-flash-lite`

公式価格（1Mトークンあたり）で有料Geminiモデル中最安。

| モデル | 入力 | 出力 |
|---|---|---|
| **gemini-3.1-flash-lite** | **$0.25** | **$1.50** |
| gemini-3.5-flash-lite | $0.30 | $2.50 |
| gemini-3.5-flash / gemini-3.6-flash | $1.50 | $7.50〜$9.00 |

実測した最初の文字までの時間も1,090msで、取材の相手として十分速い。`defaultModel` をこれに変更する。

### バックアップ: `gemma-4-26b-a4b-it`

既定モデルの呼び出しが**失敗したとき**（404、その他のエラー）に、**1回だけ**自動的にこのモデルへ切り替えて再試行する。gemma系は無料枠のため実測で初動16〜19秒と遅いので、常用ではなく「既定が使えないときの保険」に限定する。

- 再試行は1往復のみ。バックアップも失敗したら、通常のエラー表示（原則4：AIが使えなくてもエディタは動く）に落ちる
- 作者には「別のモデルで応答しています」のような**1行の状況表示**を出す（黙って切り替えない。原則3の「待ち時間を無言にしない」と同じ考え方で、切り替えも無言にしない）
- 設定画面の一覧には、既定・バックアップの区別が分かるよう軽く印を付ける（例: バックアップの項目に「(バックアップ)」と添える）

## 3. Geminiの呼び方（`src/ai.js`）

```js
export function getKey() / setKey(key) / hasKey()
export function getModel() / setModel(id)
export async function listModels(transport?)          // -> [{id, label}]
export async function ask({ chapter, scene, history, userText, onChunk, transport })
  // -> { reply: string, proposals: [{entity, aliases, text, surface, dc}] }
export function parseReply(raw)                        // -> { reply, proposals }
```

### 応答の形

**構造化出力(responseSchema)は使わない。** 流しながら表示できなくなるため（原則3）。代わりに、プロンプトで次の形を指示する。

```
（ここに作者への返事を、ふつうの日本語で書く）

```json
{"proposals":[{"entity":"封鎖の木柵","aliases":["柵","木柵"],"text":"…","surface":"…","dc":8}]}
```
```

- `streamGenerateContent` で受け取り、**```json より前の部分を `onChunk` で流す**。作者は待たされている感じを持たない
- 受信が終わってから ```json ブロックを解釈する
- **`parseReply` は絶対に例外を投げない。** JSONブロックが無い／壊れている場合は `proposals: []` を返し、`reply` はそのまま返す。作者の会話は失わない（原則4）

### プロンプトに入れるもの

- 章の題名と `quest`
- 今の場面の `name` / `brief` / `direction`
- 既にある `secrets` の `entity` と `text`（重複を提案させないため）
- これまでの会話
- **作者に内部ID・`trigger`・条件式を書かせないこと**、`aliases` は「作者が呼びそうな言い方」であること、を指示に含める
- 一度に提案するのは**最大3件**。それ以上出さない
- **一度に1つだけ質問する**

## 4. 採用したときの流れ

1. カードの内容から `secrets[]` の1件を作る。**`id` はエディタが自動で振る**（既存の採番規則に従う）。`trigger` は空でよい
2. 下書き（`gamebook:draft`）へ保存する
3. **`inspect()` を走らせて結果を右のパネルへ反映する**
4. 手詰まりや不整合が増えた場合、その場でカードの近くに出す。**採用を取り消せるようにする**

作者が判断するのは「面白いか」だけでよい。完走できるかは機械が答える。

## 5. フォームを折りたたむ

場面の編集画面で、`調べられるもの` 以下のフォームを既定で閉じた状態にし、`入力欄を見る` で開く。開いた状態は覚えておく（`localStorage`）。

**削除はしない。** 直したいときに見える場所として残す。

## 6. AIが使えないとき

キーが無い、通信に失敗した、モデル一覧が取れない、応答が壊れている。**いずれの場合も、エディタは今までどおり使えること。** 相談パネルに1行で状況と次の一手を出す。

- キーが無い → 「Geminiのキーを設定すると、会話で場面を作れます」＋設定を開くボタン
- 通信に失敗 → 「つながりませんでした。もう一度試すか、下の入力欄で直接書けます」

エラーで謝らない。何が起きて、どうすればよいかだけを書く。

## 7. 検査（`test/ai.test.mjs`）

**通信しない。** `transport` を差し替えて、決まった応答を返させる。

1. **整った応答から提案を取り出せる**（返事とJSONブロックの両方がある）
2. **JSONブロックが無い応答**は、返事だけが残り提案0件になる（会話として成立する）
3. **JSONが壊れている応答**は、例外を投げずに提案0件になり、返事は失われない
4. **提案を採用した章が `inspect()` を通る**（`structure` にエラーが増えず、`play.cleared > 0` のまま）

4 が最も大事である。AIが書いたものが、実際に遊べる章のままであることを機械が確かめている。

`package.json` の `test` に `node test/ai.test.mjs` を足す。
