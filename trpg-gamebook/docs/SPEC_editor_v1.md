# ストーリーエディタ v1 仕様

作業対象: `/Users/yasuda_k/Desktop/Terminus/trpg-gamebook`

## 目的

`data/chapter_01.json` を、JSONを直接触らずに編集する。そして**「この章は完走できるか」を編集画面がその場で答える**。

後者がこのエディタの中心である。2026-08-12に、この章データには「シーン3の出口が存在しないシーンを指す」「シーン4に出口が無くエンディングへ到達できない」という2件の欠陥が入っていたが、どちらも人間が実際に最後まで遊ぶまで誰も気付かなかった。エディタが答えるべきはここである。

## 作るファイル

| ファイル | 内容 |
|---|---|
| `editor.html` | 画面（CSSを内包。プレイヤーと同じトークンを使う） |
| `src/editor.js` | 画面の描画と入力の受け渡し |
| `src/validate.js` | 検査。**進行の判定を再実装せず、既存関数を呼ぶ** |
| `test/validate.test.mjs` | 検査そのものの検査 |

**書き換えないファイル**: `src/progression.js`、`src/inventory.js`、`src/gamebook.js`、`data/chapter_01.json`、`test/playthrough.test.mjs`。

`index.html` と `src/ui.js` は、後述の「下書きの読み込み」の1点だけ変更してよい。

## 1. データの持ち方

サーバーが無いので、編集中の章は **localStorage の `gamebook:draft`** に置く。

- エディタ起動時: `gamebook:draft` があればそれを読む。無ければ `data/chapter_01.json` を読む
- 編集するたびに `gamebook:draft` へ保存する（明示的な保存ボタンは要らない）
- 「`.json`を書き出す」ボタン: 現在の内容を `chapter_01.json` としてダウンロードする（Blob + `<a download>`）
- 「下書きを捨てる」ボタン: `gamebook:draft` を消して `data/chapter_01.json` に戻す。**押す前に確認を取る**

**プレイヤー側の変更（これだけ）**: `src/ui.js` の章読み込みを、`gamebook:draft` があればそちらを優先する形にする。無ければ従来どおり `data/chapter_01.json`。これで「編集 → タブを切り替えてすぐ試す」が成立する。下書きで遊んでいるときは、帯にそれと分かる表示を出す。

## 3. 編集する項目

**プレイヤー v1 が実際に読む項目だけを出す。** それ以外（画像、NPC、同行者、演出メモ）は v1 では出さない。

### 場面（intro / scene / ending 共通）

| 画面の名前 | JSONのキー |
|---|---|
| 場面名 | `name` |
| 導入文 | `brief` |
| 進めないときの文 | `blockedText` |

### 調べられるもの（`secrets[]`）

作者に内部IDを書かせない。**`id` はエディタが自動で振る**（`s2a` 形式ではなく、既存と衝突しない `sc<シーン番号>_<連番>` でよい。既存の秘密の `id` は変更しない）。

| 画面の名前 | JSONのキー | 補足 |
|---|---|---|
| 要素名 | `entity` | 「封鎖の木柵」 |
| 呼び名 | `aliases[]` | 読点区切りの1行で入力させる。「柵、木柵、バリケード」 |
| 調べたときに分かること | `text` | 開示される本文 |
| 見た目の説明 | `surface` | 任意 |
| 調べにくさ | `dc` | 数値。既定8 |

`trigger` は通常画面に出さない。既存の値は保持する（消さない）。

### 行き先（`exits[]`）

| 画面の名前 | JSONのキー | 入力形式 |
|---|---|---|
| どこへ | `to` | **他の場面から選ぶ選択肢**にする。自由入力にしない（`to: 0` のような壊れ方を入口で防ぐ） |
| 進むときの言葉 | `match[]` | 読点区切り |
| 必要な発見 | `requires.secretsAll` | **同じ場面の秘密からの複数選択**にする |
| 進めないときの文 | `blockedText` | |
| 到着時の文 | `text` | |

### 重要な決断（`decision`、シーンに1件まで）

| 画面の名前 | JSONのキー |
|---|---|
| 問いかけ | `prompt` |
| 選択肢の見出し | `choices[].label` |
| 選ぶと起きること | `choices[].input` |

`choices[].input` は、その場面の調査・遭遇・出口のどれかへ解決できなければならない。**入力欄の下に、解決できるかどうかを即座に表示する**（`decisionInputResolves` を使う）。解決できない場合、何に解決させたいのかの候補（その場面の秘密の `${entity}を調べる`、遭遇の `triggerTerms`、出口の `match`）を並べて選ばせる。

### 遭遇（`encounters[]`）

| 画面の名前 | JSONのキー |
|---|---|
| 起きるきっかけの言葉 | `triggerTerms[]`（読点区切り） |
| 必要な発見 | `requiredElements[]`（**同じ場面の秘密の要素名・呼び名から選ぶ**） |
| 始まりの文 | `onsetText` |
| 相手 | `enemy.name` と `enemy.hp` だけ。その他の既存フィールドは保持する |
| 倒すと分かること | `enemy.revealOnDefeat`（**同じ場面の秘密から選ぶ**） |

## 4. 検査（`src/validate.js`）— このエディタの中心

**進行の判定を再実装しない。** 既存の `progression.js` / `gamebook.js` を呼ぶ。

```js
export function inspect(chapter)   // -> { structure: [...], play: {...} }
```

### 4.1 構造の検査（`structure`）

即座に返る静的な検査。1件ごとに `{level: "error"|"warn", where, message}` を返す。

| 検査 | 使う関数 |
|---|---|
| 出口の `to` が実在する場面を指すか | `exitTargetIndexIn`。`"ending"` / `"end"` も有効として扱う |
| 出口の `requires.secretsAll/Any` が実在する秘密の `id` か | 章内の全 `secrets[].id` と突き合わせ |
| 秘密の `id` が章内で重複していないか | |
| 決断の `choices[].input` が解決できるか | `decisionInputResolves` |
| 決断の `id` が章内で一意か | |
| 遭遇の `requiredElements` が、その場面の秘密の `entity`／`aliases` に存在するか | `encounterRequiredElementsMet` と同じ突き合わせ |
| 遭遇の `enemy.revealOnDefeat` が、その場面の秘密の `id` か | |
| **出口を1つも持たない場面が無いか**（エンディングを除く） | 今回の欠陥がこれ |
| 調査で開けない秘密が、他のどこからも開示されないまま `requires` に使われていないか | `trigger`も`aliases`も持たず、どの `revealOnDefeat` にも指定されていない秘密 |

### 4.2 遊べるかの検査（`play`）

**実物のエンジンで自動プレイする。** これが他に無い機能である。

```
50回、それぞれ違う固定 seed で:
  newGame(chapter, {rng: seeded(seed)})
  200手番を上限に、candidates(state) が返した中から rng で1つ選んで act する
  結果を分類する: 完走 / 死亡 / 手詰まり(候補が0件) / 上限到達
```

返すもの:

```js
{
  runs: 50,
  cleared: 46, died: 4, stuck: 0, ranOut: 0,
  stuckAt: [{ place: "灯りの部屋", count: 0 }],   // 手詰まりが起きた場所と回数
  medianTurns: 18
}
```

**「手詰まり」と「死亡」を必ず分けて表示する。** 手詰まりはデータの欠陥、死亡は難易度の問題であり、作者が取るべき行動が違う。完走0件のときは、最も多く止まった場所を大きく出す。

自動プレイは編集のたびに走らせてよいが、**入力のたびに走らせない**（打鍵ごとに50回走ると重い）。入力が止まって400ms後、または「検査する」ボタンで走らせる。

## 5. 検査そのものの検査（`test/validate.test.mjs`）

`inspect()` が実際に欠陥を見つけることを確認する。**現物の `data/chapter_01.json` を読み、わざと壊してから検査する。**（元ファイルは書き換えない。読み込んだオブジェクトを複製して壊す）

1. 無傷の `chapter_01.json` → `structure` に `error` が0件、`play.cleared > 0`
2. シーン3の出口の `to` を `0` に書き換える → `structure` に「実在しない場面を指す」エラーが出る
3. シーン4の `exits` を空にする → 「出口を持たない場面」のエラーが出て、**`play.stuck > 0` になる**
4. 決断の `choices[0].input` を「あああ」に書き換える → 「解決できない」エラーが出る

3 が最も大事である。静的検査と自動プレイの両方が同じ欠陥を捕まえることを示している。

`package.json` の `test` を `node test/playthrough.test.mjs && node test/validate.test.mjs` にする。

## 6. 見た目

**プレイヤー（`index.html`）の `:root` のトークンをそのまま使う。** 色を新しく作らない。同じ作品の表と裏なので、揃っている必要がある。

```
--stone #0F1418   地  |  --soot #171E25 面  |  --ash #C9C3B7 文字
--dim   #6E7580   補助 |  --flame #E4B064 操作・強調
--heart #93C6D6   発見 |  --rust  #B25A3D 危険・エラー
```

ただし**役割はエディタ用に読み替える**。

- 検査の `error` は `--rust`、`warn` は `--flame`、問題なしは `--heart`
- 入力欄は枠線を引かず、下線1本（`--ash` 12%）。フォーカス時だけ `--flame`
- **書体はプレイヤーと逆にする。** プレイヤーは本文が明朝だが、エディタは**すべてゴシック**（`--mech`）にする。エディタは読み物ではなく道具であり、作者が書いた文章とUIの文言が同じ書体だと見分けがつかなくなる。作者の原稿を入れる欄（導入文・開示本文・問いかけ）だけ明朝にして、**「これは作品の文章だ」と分かるようにする**
- アニメーションは付けない。道具に演出は要らない
- キーボード操作で全項目に到達できること。フォーカスが見えること

## 7. やらないこと

Lorebook、シナリオ案内AI、画像、NPC、同行者、複数章、キャンペーン設定、TASからのインポート、章の新規作成、シーンの追加／削除／並べ替え。**v1 は「既にある章の中身を直す」だけ。**

戦闘の行動バリエーション（体当たり、パリィ等）も v1 では扱わない。
