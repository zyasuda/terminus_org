# 場面の追加と削除 v1

作業対象: `/Users/yasuda_k/Desktop/Terminus/trpg-gamebook`

## Goal

**作者が、白紙の場面をいくつでも作れる。**

今は6場面（イントロ／シーン1〜4／エンディング）で固定されており、場面を増やせない。そのため「白紙から3シーン続けて作る」という次の作業ができない。

## 最優先の原則

- **作者が触る場所を増やさない。** 追加は左の場面一覧の中に置く。新しい画面・タブ・モーダルを作らない
- **作者にIDを見せない。** 内部の識別子は画面に出さない
- **既存のデータを壊さない。** 既存6場面の中身・id・並びを変えない
- **`src/progression.js` と `src/inventory.js` は書き換え禁止**（mock2からの無改変移植。md5一致の制約がある）
- 依存パッケージを追加しない。ビルド無し・素のESM

## 1. 場面を追加する

左の場面一覧（`src/editor.js` の `renderToc()` が描く `#toc`）の**末尾**に `＋ 場面を追加` を置く。

押したときの動作:

1. `chapter.scenes` の末尾に、空の場面を1つ足す

```js
{ id: <既存のidの最大値 + 1>, name:"", brief:"", blockedText:"", secrets:[], exits:[], encounters:[] }
```

- **`id` は既存の `scenes[].id` の最大値 + 1。** 数値。既存のidと衝突させないこと。`scenes` が空なら 1
- `decision` は持たせない（`null` も入れない。キーごと置かない。既存の場面と同じ形にする）

2. 一覧を描き直し、**その新しい場面を選択した状態にする**
3. 保存する（既存の `touch()` を使う。新しい保存経路を作らない）

**追加した直後は `exits` が空なので、検査に「出口を持たない場面がある」がエラーとして出る。これは正しい挙動。** 作者に次にやることを伝えている。抑制しないこと。

一覧での表示: 場面名が空のときは `シーン5　名前のない場面` のように出す。**idだけを出さない。**

## 2. 場面を削除する

**イントロとエンディングは削除できない。** シーンだけ。

置き場所: 場面の編集画面（`nodeEditor`）の末尾。既存の `.actions` の並びに `この場面を削除` を置く（`class="danger"` を付ける。既存の削除ボタンと同じ見た目）。

押したときの動作:

1. `confirm()` で確認する（**必須**。既存の「下書きを捨てる」と同じ扱い）
2. `chapter.scenes` から取り除く
3. **選択をイントロに戻す**（`selected.node = "intro"`）。`scene:N` の N は配列の添字なので、削除すると後ろの場面の添字がずれる。**ずれた添字を選んだままにしないこと**
4. 保存し、一覧と編集画面を描き直す

**削除した場面を指していた `exit.to` は直さない。** 検査が「出口が実在しない場面を指している」とエラーで出す。それが作者への通知になる。**黙って直さない。**

## 3. どこからも来られない場面を検査する

`src/validate.js` の `structureFor()` に1件足す。**`warn`**（`error` にしない）。

**判定**: どの場面の `exits[].to` からも指されていないシーン。イントロは対象外（開始地点なので指されなくて当然）。エンディングも対象外。

メッセージ: `どこからも来られない場面がある`

**なぜ要るか**: 場面を足しても、どこからも繋がなければ自動プレイは一度も訪れない。検査の数字（完走・死亡・手詰まり）に一切現れず、**作者は「問題なし」と表示されたまま、届かない場面を書き続けることになる。**

`exit.to` の照合には既存の `exitTargetIndexIn(chapter.scenes, exit.to)` を使うこと。`"ending"` / `"end"` はエンディングを指す。**新しい照合を書かないこと。**

## 4. 検査（`test/validate.test.mjs` に追加）

既存の検査は全部残す。**通信しない。**

1. どこからも指されていないシーンを足すと `warn` が出る
2. そのシーンへの `exit` を足すと警告が消える
3. **この項目が `error` を増やさない**（既存の「無傷の章は構造エラーなく完走できる」が緑のまま）

追加・削除は `src/editor.js`（DOM依存）にあるためNodeの検査に載せられない。**無理にテストを書かず、書けない理由を報告すること。** ブラウザでの確認はこちらで行う。

## 5. やらないこと

- 場面の並べ替え
- 章の新規作成、複数章、ファイルを開く
- イントロ・エンディングの追加や削除
- 削除時に `exit.to` を自動で直すこと（検査に出させる）
- AIへの問い合わせ
- 新しい画面・タブ・モーダル

## 6. 完了の報告に含めること

- `npm test` の実際の出力（既存21件 + 追加3件）
- 追加・削除がテストで検証できなかった理由
- 仕様どおりに書けなかった箇所とその理由
- ブラウザでの見た目は**未確認と明記すること**
