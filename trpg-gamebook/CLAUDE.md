# gamebook専用作業ガイド

## 適用範囲

このファイルは `trpg-gamebook` 内の編集・検証作業に適用します。実装経緯、個別シナリオ、設計の背景はBORGまたは `docs/` を参照します。

## 基本姿勢

- 複雑な内容は、関係が理解しやすくなる場合に図や表で示す
- 簡潔かつ直接的に書き、確認できた事実と推測を区別する
- 調査が必要な場合は、実コードと一次情報源を優先する
- ユーザーの目標と制約から逸脱しない。不用意に質問しない
- 子Agentは必要な場合だけ使い、無意味な並列作業をしない
- 依頼と無関係なリファクタリング、抽象化、データ変更をしない
- 既存のセーブデータ、シナリオJSON、画像、他者の変更を保護する
- 実際にテスト・実プレイ・画面確認を行い、見た目だけで完了と判断しない
- 重要な判断、変更、検証結果だけを報告する
- 可能な限り、codexへ実装作業を非同期で委譲し、完了後は妥当性のチェックを行う

## データ読込

`data/chapter_01.json` を `fetch` で読む。ビルド無し・依存パッケージ無しのESM。`file://` では読めないので、必ずローカルサーバー経由で開く。

```
npm run serve                 # → http://localhost:8123/（キャッシュ無効。http.serverは使わない）
```

出典はmock2 spike（`codex/mock2-candidate-spike`）の `chapter_01.json`。**mock2側のJSONは正本ではない**（main側はシーン3の出口が壊れ、spike側はシーン4の出口が欠落していた。`data/` のコピーだけが両方を満たす）。mock2側のJSONを編集・上書きしない。

## 状態・セーブ・進行

セーブは無い。`newGame()` で毎回最初から。進行の核は次の3つだけ。

| 関数 | 役割 |
|---|---|
| `newGame(chapter, {rng})` | 初期状態。`rng` を渡せば出目が再現する（テストは必ず渡す） |
| `candidates(state)` | 今押せる選択肢。決断イベント中は通常候補の代わりに決断の選択肢を返す |
| `act(state, input)` | 状態を更新し、描画用の `events[]` を返す |

`act` の解決順は **決断 → 交戦中の行動 → 遭遇の発火 → 調査 → 出口**。新しい解決経路を足さない。手番は実際に何かが起きたときだけ進む（`unknown` / `blocked` では進めない）。

接近度は `approachLevel(turn, sceneEnteredTurn)`。数値は画面に出さず、ランタンの光溜まりが狭まることで伝える。

```
npm test                      # 完走・弱点で詰まない・未解決入力で状態が変わらない の3件
```

## UIを足す前に（2026-08-13 追加）

同じ失敗を2回した。決断の選択肢欄と、連鎖の図。どちらも**エンジンのデータの形をそのまま作者に見せた**。どちらも「表示されること」をPlaywrightで確かめ、「使えること」を確かめなかった。

UIを足す前に、この3つを必ず行う。仕様書を書く前、委譲する前。

1. **作業手順を手数まで書き出す。** 完成した画面の見本ではなく、作者が押す順番を全部書く。**3手を超えるなら設計をやり直す。** 連鎖の図は、見本をチャットで見せて承認を得たが失敗した。見せたのが「出来上がり」で「作る手順」ではなかったため。壊れたのは表示ではなく作成だった（実際は7手・2画面往復）
2. **その手順を、内部を知らない状態で1回通す。** `button[data-add='secret']` のようなセレクタで押すのは、内部を知っている者の経路であって検証ではない。作者と同じ画面・同じ順で1つの作業を完遂できなければ、作らない
3. **触る場所が増えるなら作らない。** 既にある場所（会話・検査・実プレイ）に入るかを先に問う。新しい入力欄・新しいパネル・新しい図は、それ自体が失敗の兆候

**確認は図ではなく実プレイ。** 下書きは `http://localhost:8123/` でそのまま遊べる（`src/ui.js` が `gamebook:draft` を先に読む）。作者にとって意味のある確認はこれひとつ。

## 章の作り方（2026-08-13 決定）

**白紙から作者に作らせない。AIが下書きを書き、作者が直す。**

1. Claudeが章のJSONを書く
2. 作者が `.jsonを読み込む` で開く
3. 作者が直す。取材は「何を作るか」ではなく**辻褄が合わないところ**に使う

エディタは生成の道具ではなく、**見直しと調整の道具**。生成は会話、判断は作者、正しさは `inspect()` と実プレイ。
